# m12.4 — Order dari blob JSON ke tabel relasional (Starter)

**Tujuan:** query daftar, ringkasan, dan recovery yang biayanya tidak tumbuh linear dengan jumlah order, plus migrasi data lama yang aman.
**Yang perlu dibangun:** migrasi `order-001-relational-orders` di `services/order-service/src/migrations.ts` (tabel `orders` + `order_lines`, indeks, pemindahan data dari `records`) dan isi `services/order-service/src/order-table.ts` sebagai query SQL. Di starter, `order-table.ts` membaca semua order dari key/value store lalu memfilter di JavaScript; antarmukanya sudah final, jadi kode lain tidak perlu diubah.
**Acceptance:** `orders-relational.test.ts` lulus: migrasi data lama, `EXPLAIN QUERY PLAN` memakai indeks, cursor keyset tidak mengulang/melewati baris. Seluruh tes order-service tetap lulus.

## Cara Debugging

- Indeks tidak dipakai → urutan kolom indeks harus mengikuti `WHERE` lalu `ORDER BY` (`user_id, created_at DESC, id DESC`).
- Halaman berikutnya mengulang order → cursor memakai pembanding baris `(created_at, id) < (?, ?)`, bukan hanya `created_at`.
- Migrasi gagal di tengah → satu migrasi = satu transaksi; storage membuat backup `pre-<nama>` sebelum menyentuh data.
- Status di kolom dan di JSON berbeda → jangan simpan field yang sama dua kali; kolom adalah sumber kebenaran.
