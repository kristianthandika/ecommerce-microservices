# m2.3 — order-service dengan Chaos Test

| Branch awal                | Kunci jawaban               | Waktu     | Sebelumnya | Berikutnya |
| -------------------------- | --------------------------- | --------- | ---------- | ---------- |
| `starter/m2.3-order-chaos` | `solution/m2.3-order-chaos` | 150 menit | m2.2       | m3.1       |

## Yang akan Anda pelajari

- Memanggil service lain lewat resilient HTTP client buatan m2.2.
- **Graceful degradation**: bila product-service mati, order-service tetap menjawab
  dengan cepat (503), tidak menggantung dan tidak crash.
- Menulis **chaos test**: tes yang sengaja mematikan dan menghidupkan dependency.

## Kondisi awal

auth-service, product-service, dan `@ecommerce/resilient-http-client`, 23 tes lulus.

```bash
git switch starter/m2.3-order-chaos
npm ci && npm run build:packages
```

## Konsep singkat

Saat membuat pesanan, order-service bertanya ke product-service: "produk ini ada?
harganya berapa? stoknya cukup?". Jawabannya dibekukan ke dalam pesanan (harga saat
dipesan tidak boleh berubah bila katalog berubah besok).

Pertanyaan yang diuji chaos test: **apa yang terjadi bila product-service lambat,
error, atau mati?**

| Kondisi product-service | Yang diharapkan dari order-service                                |
| ----------------------- | ----------------------------------------------------------------- |
| sehat                   | `201` dan pesanan tersimpan                                       |
| tidak menjawab (hang)   | `503` setelah timeout, bukan menggantung                          |
| gagal berulang kali     | breaker OPEN; panggilan ke product-service **berhenti bertambah** |
| pulih                   | setelah `resetTimeoutMs`, breaker menutup dan pesanan sukses lagi |

## Langkah-langkah

### Langkah 1 — Siapkan workspace dari pola product-service

```bash
mkdir -p services/order-service/src/middleware services/order-service/tests
cp services/product-service/tsconfig.json services/order-service/
cp services/product-service/src/types.d.ts services/order-service/src/
cp services/product-service/src/middleware/{errors,validate,require-auth}.ts services/order-service/src/middleware/
```

`package.json`: nama `order-service`, dependency seperti product-service ditambah
`"@ecommerce/resilient-http-client": "*"`. Salin dan sesuaikan `app.ts` serta
`index.ts`. Lalu `npm install`.

### Langkah 2 — Konfigurasi resilience dari environment (`src/config.ts`)

```ts
export const config = {
  serviceName: 'order-service',
  port: Number(process.env.PORT || process.env.ORDER_SERVICE_PORT || 3003),
  authServiceUrl: process.env.AUTH_SERVICE_URL || 'http://localhost:3001',
  productServiceUrl: process.env.PRODUCT_SERVICE_URL || 'http://localhost:3002',
  jwtIssuer: process.env.JWT_ISSUER || 'auth-service',
  corsOrigin: process.env.CORS_ORIGIN || 'http://localhost:5173',
  resilience: {
    timeoutMs: Number(process.env.PRODUCT_TIMEOUT_MS || 1500),
    retries: Number(process.env.PRODUCT_RETRIES || 2),
    baseDelayMs: Number(process.env.PRODUCT_RETRY_BASE_MS || 100),
    failureThreshold: Number(process.env.PRODUCT_CB_THRESHOLD || 3),
    resetTimeoutMs: Number(process.env.PRODUCT_CB_RESET_MS || 5000),
  },
} as const;
```

Semua angka bisa diubah lewat environment. Chaos test memakai angka kecil supaya
cepat selesai.

### Langkah 3 — Klien ke product-service (`src/product-client.ts`)

Buat klien **sekali** di level modul. Bila dibuat ulang di setiap request, state
breaker hilang dan breaker tidak pernah OPEN.

```ts
const client = createResilientClient({ name: 'product-service', ...config.resilience });

export async function fetchProduct(id: string, { correlationId }: { correlationId?: string } = {}) {
  const headers: Record<string, string> = {};
  if (correlationId) headers[CORRELATION_ID_HEADER] = correlationId; // dipakai di m3.2
  let res: Response;
  try {
    res = await client(`${config.productServiceUrl}/products/${id}`, { headers });
  } catch (err) {
    if (err instanceof CircuitOpenError)
      throw new AppError(503, 'Layanan produk sedang tidak tersedia (circuit open)');
    throw new AppError(503, 'Gagal menghubungi layanan produk');
  }
  if (res.status === 404)
    throw new AppError(404, `Produk ${id} tidak ditemukan`, undefined, 'NOT_FOUND');
  if (!res.ok) throw new AppError(502, 'Respons tidak terduga dari layanan produk');
  return ((await res.json()) as { product: RemoteProduct }).product;
}
```

### Langkah 4 — Logika pesanan (`src/orders.ts`)

`createOrder({ userId, items }, ctx)`:

1. Ambil semua produk **paralel** dengan `Promise.all(items.map(...fetchProduct))`.
   Satu putaran jaringan, bukan satu per item.
2. Untuk setiap item: stok kurang dari `quantity` →
   `AppError(409, 'Stok produk … tidak cukup', undefined, 'OUT_OF_STOCK')`.
3. Bentuk baris pesanan `{ productId, name, unitPrice, quantity, subtotal }` dan
   `total`.
4. Simpan di `Map` dengan status `CONFIRMED` dan `createdAt`.

Tambahkan `listOrdersForUser(userId)` dan `getOrder(id, userId)`. Pesanan milik orang
lain dijawab **404**, bukan 403, supaya ID pesanan orang lain tidak bisa ditebak.

### Langkah 5 — Route (`src/routes.ts`)

```ts
const orderSchema = z.object({
  items: z
    .array(
      z.object({
        productId: z.string().min(1).max(100),
        quantity: z.number().int().positive().max(1000),
      }),
    )
    .min(1)
    .max(50), // batas array: satu request tidak boleh memicu ratusan panggilan
});

router.post('/orders', requireAuth, validate(orderSchema), async (req, res) => {
  const order = await createOrder(
    { userId: String(req.user?.sub), items: (req.validated as OrderInput).items },
    { correlationId: req.id ? String(req.id) : undefined },
  );
  res.status(201).json({ order });
});
router.get('/orders', requireAuth, (req, res) =>
  res.json({ orders: listOrdersForUser(String(req.user?.sub)) }),
);
router.get('/orders/:id', requireAuth, (req, res) =>
  res.json({ order: getOrder(String(req.params.id), String(req.user?.sub)) }),
);
```

## Menguji hasil kerja

```bash
git checkout solution/m2.3-order-chaos -- services/order-service/tests
npm test --workspace=services/order-service
```

Chaos test menjalankan **tiga server sungguhan di port acak**: JWKS palsu,
product-service palsu yang bisa diubah perilakunya (`ok`, `503`, `hang`), dan
order-service Anda. Tes yang harus lulus:

- `(1) alur normal saat product-service hidup → order dibuat (201)`
- `(2) product-service tidak merespons (timeout) → order TETAP merespons graceful (503, bukan hang/crash)`
- `(3) setelah circuit breaker OPEN, panggilan ke product-service TIDAK bertambah linear`
- `(4) setelah product-service pulih & resetTimeout lewat → breaker menutup, order sukses lagi`

Pelajari berkas tesnya. Perhatikan cara tes mengisi env `PRODUCT_*` **sebelum**
mengimpor aplikasi, dan cara `afterAll` menutup ketiga server.

## Kriteria lulus

- [ ] Keempat chaos test lulus dan proses tes selesai sendiri (tanpa `--forceExit`).
- [ ] Semua tes sebelumnya (auth, product, resilient client) tetap lulus.
- [ ] Coba manual: jalankan ketiga service, buat pesanan, matikan product-service,

## Bila ada masalah

| Gejala                                | Solusi                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------- |
| Tes menggantung                       | `afterAll` harus menunggu `server.close()` (bungkus dalam `new Promise`). |
| Breaker tidak pernah OPEN di tes      | Klien dibuat di dalam `fetchProduct`. Pindahkan ke level modul.           |
| Jumlah panggilan terus naik saat OPEN | Pastikan breaker membungkus retry (urutan komposisi di m2.2).             |
| 500 alih-alih 503                     | Error dari klien tidak diubah menjadi `AppError(503, …)`.                 |
