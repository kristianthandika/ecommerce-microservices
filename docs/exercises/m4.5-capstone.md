
## Langkah-langkah

### Langkah 1 — Chaos test manual

Siapkan tiga jendela: browser di dashboard (http://localhost:3000, sudah login),
satu terminal untuk perintah, satu terminal untuk log (`docker compose logs -f gateway
order-service`).

| Langkah | Perintah / aksi                        | Yang harus Anda amati                                                     |
| ------- | -------------------------------------- | ------------------------------------------------------------------------- |
| 1       | `curl -s localhost:8080/health`        | `"status":"ok"`, semua service `up`                                       |
| 2       | `docker compose stop product-service`  | widget: baris `product` menjadi DOWN dalam ≤ 3 detik                      |
| 3       | `curl -i localhost:8080/health`        | HTTP 503, `"status":"degraded"`                                           |
| 4       | Buat pesanan dari dashboard            | pesan error yang rapi (503), halaman tidak macet                          |
| 5       | Ulangi langkah 4 beberapa kali         | jawaban makin cepat: circuit breaker OPEN, order-service berhenti mencoba |
| 6       | `docker compose start product-service` | tunggu `healthy`; widget kembali hijau                                    |
| 7       | Tunggu ±5 detik, buat pesanan lagi     | berhasil: breaker HALF_OPEN → CLOSED                                      |

Catat waktu dan hasil setiap langkah. Catatan itulah bukti capstone Anda.

Coba juga load test:

```bash
npm run loadtest
```

Sebagian besar request akan dijawab 429 karena rate limit gateway (100/menit per IP).
Itu **perlindungan yang bekerja**, bukan kegagalan.

### Langkah 2 — `docs/PRODUCTION-CHECKLIST.md`

Tulis lima bagian. Untuk masing-masing jelaskan **kondisi sekarang**, **risikonya**,
dan **langkah menuju produksi**:

1. **Database per service.** Sekarang data di memory dan hilang saat restart. Setiap
   service butuh database sendiri yang persisten (bukan satu database bersama, ingat
   m1.1).
2. **Secret management.** Password admin demo dan konfigurasi ada di environment
   variable biasa. Di produksi: secret manager, rotasi kunci RSA.
3. **Message queue.** Pembuatan pesanan masih memanggil product-service secara
   sinkron. Kapan perlu antrean (misalnya RabbitMQ, Kafka) dan event?
4. **Distributed tracing penuh.** Sekarang span hanya dicetak ke console gateway.
   Di produksi: semua service, dikirim ke backend tracing.
5. **CI/CD per service.** Tes, build image, dan deploy otomatis untuk setiap service.

### Langkah 3 — `README.md` di root

Pembaca README adalah orang yang baru meng-clone repo. Minimal berisi:

- arsitektur (diagram teks seperti di Panduan Pemula) dan peran tiap service;
- prasyarat (Docker Desktop, Node.js 24);
- cara menjalankan: `docker compose up --build`, tabel URL (3000, 8080, 8080/health),
  dan akun demo;
- pengembangan lokal tanpa Docker (`npm ci`, `npm run build:packages`, `npm run dev:all`);
- perintah tes, typecheck, lint;
- prosedur chaos test dari langkah 1;
- tabel singkat **Docker Compose vs Kubernetes** (cakupan, scaling, service discovery,
  health/restart, config/secret, kapan dipakai).

Uji README Anda: clone repo ke folder baru, ikuti README **persis** apa adanya, dan
perbaiki setiap langkah yang membuat Anda harus menebak.

### Langkah 4 — `DECISIONS.md`

Catat keputusan teknis yang tidak terlihat dari kode, dengan alasannya. Contoh:
mengapa TypeScript dijalankan tanpa build step, mengapa CORS dipasang di gateway dan
di service, mengapa penyimpanan in-memory, mengapa admin demo hanya untuk pelatihan.

## Bila ada masalah

| Gejala                                        | Solusi                                                                                  |
| --------------------------------------------- | --------------------------------------------------------------------------------------- |
| Breaker tidak pernah pulih                    | Beri jeda lebih dari `PRODUCT_CB_RESET_MS` (bawaan 5 detik) setelah service hidup lagi. |
| Widget tidak berubah saat service dimatikan   | Pastikan Anda memakai `docker compose stop`, bukan `pause`.                             |
| Setelah restart, akun yang didaftarkan hilang | Wajar: penyimpanan masih di memory. Lihat checklist item 1.                             |
