# m1.2 — Bootstrap auth-service & Middleware Keamanan

| Branch awal                   | Kunci jawaban                  | Waktu    | Sebelumnya | Berikutnya |
| ----------------------------- | ------------------------------ | -------- | ---------- | ---------- |
| `starter/m1.2-auth-bootstrap` | `solution/m1.2-auth-bootstrap` | 90 menit | m1.1       | m1.3       |

## Yang akan Anda pelajari

- Pola service Express 5 yang siap dipakai: **app factory** terpisah dari `listen()`.
- Middleware keamanan: `helmet`, `cors`, `express-rate-limit`.
- Error handler terpusat yang selalu menjawab JSON dan tidak membocorkan stack trace.
- Validasi input dengan `zod`, dan cara Express 5 menangkap error dari handler async.

## Kondisi awal

Belum ada folder `services/`. Anda membuat service pertama dari nol.

```bash
git switch starter/m1.2-auth-bootstrap
npm ci
npm run build:packages
```

## Konsep singkat

Urutan middleware Express penting. Request melewatinya dari atas ke bawah:

```
helmet → cors → express.json → logger → rate-limit → route → 404 → error handler
```

Error handler **harus didaftarkan paling akhir**. Express mengenalinya dari jumlah
parameternya (empat: `err, req, res, next`).

Express 5 punya kemudahan penting: bila handler `async` melempar error, Express
otomatis meneruskannya ke error handler. Anda tidak perlu `try/catch` di setiap
route.

### Langkah 2 — Konfigurasi dari environment

`src/config.ts` mengumpulkan semua pengaturan dari `process.env`, dengan default yang

```ts
export const config = {
  serviceName: 'auth-service',

} as const;
```

### Langkah 3 — Error aplikasi dan error handler

`src/middleware/errors.ts` berisi tiga hal:

1. `class AppError extends Error` dengan `status`, `code`, dan `details` opsional.
   Kode lain cukup menulis `throw new AppError(404, 'Produk tidak ditemukan')`.
2. `notFoundHandler` — menjawab `404 { error: { message: 'Resource tidak ditemukan', code: 'NOT_FOUND' } }`.
3. `errorHandler(err, req, res, _next)`:
   - `ZodError` → `400` dengan `code: 'VALIDATION_ERROR'` dan daftar field yang salah;
   - `AppError` → status dan pesan dari error itu;
   - selain itu → `500 { error: { message: 'Terjadi kesalahan internal', code: 'INTERNAL' } }`.
     Jangan pernah mengirim `err.message` atau `err.stack` mentah ke klien.

Semua jawaban error memakai **bentuk yang sama**: `{ error: { message, code, details? } }`.
Frontend nanti cukup membaca satu bentuk.

### Langkah 4 — Middleware validasi

`src/middleware/validate.ts`:

```ts
import type { Request, Response, NextFunction } from 'express';
import type { ZodTypeAny } from 'zod';

export function validate(schema: ZodTypeAny, source: 'body' | 'query' | 'params' = 'body') {
  return (req: Request, _res: Response, next: NextFunction): void => {
    req.validated = schema.parse(req[source]); // ZodError → errorHandler → 400
    next();
  };
}
```

TypeScript belum tahu `req.validated`. Tambahkan `src/types.d.ts`:

```ts
declare global {
  namespace Express {
    interface Request {
      validated?: unknown;
    }
  }
}
export {};
```

### Langkah 5 — App factory

`src/app.ts` mengekspor `createApp()` yang **mengembalikan app tanpa `listen()`**.
Tes memakai app ini langsung lewat supertest tanpa membuka port.

```ts
export function createApp({ logger = createLogger(config.serviceName) } = {}): Express {
  const app = express();
  app.set('trust proxy', 1); // percayai SATU proxy (gateway), bukan semua
  app.use(helmet());
  app.use(cors({ origin: config.corsOrigin, credentials: true }));
  app.use(express.json());
  app.use(createHttpLogger(logger));
  app.use(
    rateLimit({
      windowMs: 15 * 60 * 1000,
      limit: 300,
      standardHeaders: true,
      legacyHeaders: false,
    }),
  );
  app.use('/', buildRouter());
  app.use(notFoundHandler);
  app.use(errorHandler); // WAJIB paling akhir
  return app;
}
```

### Langkah 6 — Route

`src/routes.ts`:

```ts
export function buildRouter(): Router {
  const router = Router();
  router.get('/health', (_req, res) => {
    res.json({ status: 'ok', service: 'auth-service' });
  });
  // Contoh: handler async yang melempar error, TANPA try/catch.
  router.get('/boom', async () => {
    throw new Error('contoh error yang tidak tertangani di handler');
  });
  return router;
}
```

Route `/boom` hanya untuk membuktikan error handler bekerja. Route ini dihapus di m1.3.

### Langkah 7 — Titik masuk server

`src/index.ts` membuat app, memanggil `listen`, dan menutup server dengan rapi saat
menerima `SIGTERM`/`SIGINT` (dipakai Docker saat menghentikan container):

```ts
const logger = createLogger(config.serviceName);
const server = createApp({ logger }).listen(config.port, () =>
  logger.info({ port: config.port }, `${config.serviceName} listening`),
);
for (const signal of ['SIGTERM', 'SIGINT'] as const)
  process.on(signal, () => server.close(() => process.exit(0)));
```

### Langkah 8 — Coba dari terminal

```bash
npm run dev --workspace=services/auth-service
# terminal lain:
curl -i http://localhost:3001/health        # 200 {"status":"ok",...}
curl -i http://localhost:3001/boom          # 500 {"error":{"message":"Terjadi kesalahan internal",...}}
curl -i http://localhost:3001/tidak-ada     # 404 {"error":{...,"code":"NOT_FOUND"}}
```

Perhatikan juga header `X-Content-Type-Options: nosniff` (dari helmet) dan
`RateLimit-Limit` (dari rate limiter), serta log JSON di terminal pertama.

Solution menyertakan tes `services/auth-service/tests/bootstrap.test.ts`. Ambil dan
jalankan terhadap kode Anda:

```bash

```

Tes yang harus lulus:

- `GET /health → 200 { status: "ok" }`
- `handler async yang throw → 500 JSON generik, tanpa stack trace`
- `route yang tidak dikenal → 404 JSON dengan bentuk error yang sama`
- `security header dari helmet dan header rate-limit terpasang`

## Kriteria lulus

- [ ] Keempat tes di atas lulus; `npm run typecheck` dan `npm run lint` bersih.
- [ ] Error apa pun dijawab JSON dengan bentuk `{ error: { message, code } }`, tidak pernah HTML.
- [ ] Body yang tidak valid (nanti di m1.3) dijawab 400, bukan 500.

## Bila ada masalah

| Gejala                                 | Solusi                                                                                       |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| Jawaban error berupa halaman HTML      | `errorHandler` belum didaftarkan, atau didaftarkan sebelum route. Pindahkan ke paling akhir. |
| Error tidak sampai ke error handler    | Ada `try/catch` yang menelan error. Hapus, atau lempar ulang errornya.                       |
| `errorHandler` tidak pernah terpanggil | Fungsi harus punya **empat** parameter; parameter keempat boleh bernama `_next`.             |
| `Property 'validated' does not exist`  | `src/types.d.ts` belum ada atau tidak tercakup `include` di `tsconfig.json`.                 |
