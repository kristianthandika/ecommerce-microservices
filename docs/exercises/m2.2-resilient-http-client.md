## Yang akan Anda pelajari

- **Timeout**: jangan menunggu layanan lain selamanya.
- **Retry dengan exponential backoff + jitter**: mencoba lagi tanpa membanjiri layanan yang sedang sakit.
- **Circuit breaker**: berhenti memanggil layanan yang rusak, lalu mencoba lagi dengan hati-hati.
- Menyusun ketiganya menjadi satu klien, di atas `fetch` bawaan Node, **tanpa library**.

## Konsep singkat

Setiap pembungkus (wrapper) menerima fungsi bertanda tangan `fetch` dan
mengembalikan fungsi dengan tanda tangan yang **sama**. Karena itu mereka bisa
ditumpuk seperti bawang:

```
circuitBreaker( retry( throwOnServerError( timeout( fetch ) ) ) )
```

- Setiap percobaan retry punya timeout sendiri (timeout paling dalam).
- Respons 5xx diubah menjadi error, supaya retry dan breaker bereaksi.
- Breaker paling luar: satu rangkaian retry yang habis = satu kegagalan. Saat breaker
  OPEN, ia menolak duluan, jadi retry dan fetch sama sekali tidak dijalankan.

State machine circuit breaker:

```
CLOSED ──(gagal ≥ threshold)──▶ OPEN ──(resetTimeoutMs lewat)──▶ HALF_OPEN
   ▲                                                                  │
   └──────────────(satu percobaan berhasil)────────────────────────────┤
                         (percobaan gagal) ──▶ OPEN lagi ◀────────────┘
```

### Langkah 2 — Tipe dan error

`src/index.ts`:

```ts
export type FetchFn = (url: string, options?: RequestInit) => Promise<Response>;

export class TimeoutError extends Error {
  readonly code = 'ETIMEDOUT';
  constructor(ms: number) {
    super(`Request melewati timeout ${ms}ms`);
    this.name = 'TimeoutError';
  }
}
export class CircuitOpenError extends Error {
  readonly code = 'ECIRCUITOPEN';
  constructor(name: string) {
    super(`Circuit breaker OPEN untuk "${name}"`);
    this.name = 'CircuitOpenError';
  }
}
export class ServerError extends Error {
  readonly code = 'ESERVER';
  constructor(readonly status: number) {
    super(`Server merespons ${status}`);
    this.name = 'ServerError';
  }
}
```

### Langkah 3 — `withTimeout(fetchFn, ms)`

1. Buat `AbortController`, dan `setTimeout(() => { timedOut = true; controller.abort(); }, ms)`.
2. Bila pemanggil memberi `options.signal`, teruskan pembatalannya ke controller
   (`addEventListener('abort', …)`), supaya pembatalan dari dua arah sama-sama dihormati.
3. Panggil `fetchFn(url, { ...options, signal: controller.signal })`.
4. Bila error berupa `AbortError` **dan** `timedOut` bernilai `true`, lempar
   `TimeoutError`. Pembatalan oleh pemanggil diteruskan apa adanya.
5. Di `finally`, `clearTimeout(timer)`. Tanpa itu, timer tetap hidup dan tes tidak
   pernah selesai.

### Langkah 4 — `withRetry(fetchFn, { retries = 3, baseDelayMs = 100, jitter = true })`

```ts
for (let attempt = 0; attempt <= retries; attempt += 1) {
  try {
    return await fetchFn(url, options);
  } catch (err) {
    lastError = err;
    if (attempt === retries) break;
    const exp = baseDelayMs * 2 ** attempt; // 100, 200, 400, ...
    await sleep(jitter ? Math.random() * exp : exp); // "full jitter"
  }
}
throw lastError;
```

Jitter (jeda acak) mencegah ratusan klien mencoba ulang pada detik yang persis sama
(_thundering herd_). Hanya error yang dilempar yang dicoba ulang. Respons 4xx adalah
kesalahan klien, jadi tidak dicoba ulang.

### Langkah 5 — `withCircuitBreaker(fetchFn, { failureThreshold = 5, resetTimeoutMs = 10000, name, onStateChange })`

Simpan state di **closure** (variabel di luar fungsi yang dikembalikan):

```ts
let state: CircuitState = 'CLOSED';
let failures = 0;
let nextAttempt = 0;
let probing = false;
```

Lalu untuk setiap panggilan:

1. Bila `OPEN`: sebelum `nextAttempt` → lempar `CircuitOpenError` **tanpa** memanggil
   `fetchFn`; sesudahnya → pindah ke `HALF_OPEN`.
2. Bila `HALF_OPEN`: hanya **satu** percobaan (_probe_) yang boleh lewat. Request lain
   yang datang bersamaan langsung ditolak dengan `CircuitOpenError`.
3. Berhasil → `failures = 0`, `CLOSED`.
4. Gagal → `failures += 1`. Bila sedang `HALF_OPEN` atau `failures >= failureThreshold`
   → `OPEN` dan `nextAttempt = Date.now() + resetTimeoutMs`.

### Langkah 6 — `throwOnServerError` dan `createResilientClient`

```ts
export function throwOnServerError(fetchFn: FetchFn): FetchFn {
  return async (url, options = {}) => {
    const res = await fetchFn(url, options);
    if (res.status >= 500) throw new ServerError(res.status);
    return res;
  };
}

export function createResilientClient({
  fetchImpl = fetch,
  timeoutMs = 2000,
  retries = 2,
  baseDelayMs = 100,
  jitter = true,
  failureThreshold = 3,
  resetTimeoutMs = 5000,
  name = 'upstream',
  treat5xxAsFailure = true,
  onStateChange,
}: ResilientClientOptions = {}): FetchFn {
  let layer: FetchFn = withTimeout(fetchImpl, timeoutMs);
  if (treat5xxAsFailure) layer = throwOnServerError(layer);
  layer = withRetry(layer, { retries, baseDelayMs, jitter });
  return withCircuitBreaker(layer, { failureThreshold, resetTimeoutMs, name, onStateChange });
}
```

## Menguji hasil kerja

Tes paket ini menyuntikkan `fetch` palsu, jadi tidak butuh jaringan. Ambil dari
solution:

```bash
git checkout solution/m2.2-resilient-http-client -- packages/resilient-http-client/tests
npm run build:packages
npm test --workspace=packages/resilient-http-client
```

Tes yang harus lulus:

- withTimeout: `membatalkan request yang lebih lambat dari batas waktu`,
  `meneruskan response kalau selesai sebelum timeout`,
  `pembatalan oleh caller diteruskan sebagai AbortError (bukan TimeoutError)`
- withRetry: `mencoba ulang sejumlah retries lalu berhasil`,
  `menyerah setelah retries habis dan melempar error terakhir`,
  `menggunakan delay yang membesar antar percobaan (exponential backoff)`
- withCircuitBreaker: `OPEN setelah failureThreshold, menolak cepat tanpa memanggil target`,
  `pindah ke HALF_OPEN setelah resetTimeoutMs lalu CLOSED saat sukses`,
  `HALF_OPEN hanya mengizinkan SATU probe walau ada request konkuren`
- createResilientClient: `saat OPEN, tidak memanggil fetch asli sama sekali (fail-fast)`

**Tantangan:** sebelum mengambil tes dari solution, tulis sendiri satu tes untuk
`withRetry` memakai `fetch` palsu yang gagal dua kali lalu berhasil.

## Kriteria lulus

- [ ] Sepuluh tes paket ini lulus; tes service lain tetap lulus.
- [ ] Tidak ada dependency runtime baru (hanya API bawaan Node).
- [ ] `npm run build:packages` menghasilkan `packages/resilient-http-client/dist/`.

## Bila ada masalah

| Gejala                                | Solusi                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| Breaker tidak pernah OPEN             | State dibuat ulang di setiap panggilan. Pindahkan ke luar fungsi yang dikembalikan. |
| Retry terjadi tanpa jeda              | `sleep(...)` dipanggil tanpa `await`.                                               |
| Tes menggantung setelah lulus         | Timer timeout tidak di-`clearTimeout` di `finally`.                                 |
| Pembatalan pemanggil dianggap timeout | Periksa `timedOut` sebelum mengubah `AbortError` menjadi `TimeoutError`.            |
