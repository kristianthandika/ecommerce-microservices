# m12.2 — Pembatalan order sebagai saga dengan kompensasi (Starter)

**Tujuan:** membatalkan order lintas dua service tanpa transaksi terdistribusi: niat disimpan durable, kompensasi idempoten, recovery menyelesaikan sisanya.
**Yang perlu dibangun:** `releaseReservation` di `services/product-service/src/products.ts` (idempoten, menulis _tombstone_ untuk ID yang belum punya receipt) dan `cancelOrder` di `services/order-service/src/orders.ts` (tulis `CANCELLATION_REQUESTED` dulu, lalu lepas stok; 200 bila selesai, 202 bila product-service tidak terjangkau). Di starter keduanya menjawab 501.
**Acceptance:** `cart-cancel.test.ts` (blok _order cancellation releases stock exactly once_) dan `inventory.test.ts` lulus, termasuk balapan batal-vs-reservasi yang terlambat.

## Cara Debugging

- Stok kembali dua kali → release harus memeriksa status `RELEASED` di dalam transaksi yang sama.
- Stok bocor setelah batal → reservasi yang datang belakangan untuk ID yang sudah dibatalkan harus ditolak; itulah fungsi tombstone.
- Order tertahan di `CANCELLATION_REQUESTED` → `recoverPendingOrders` sudah melanjutkan status ini lewat `release()`; pastikan `cancelOrder` menulis status itu sebelum memanggil product-service.
- 500 saat product-service mati → error 5xx dari release berarti "belum selesai", jawab 202.
