| Branch awal                  | Kunci jawaban                 | Waktu     | Sebelumnya | Berikutnya |

## Yang akan Anda pelajari

- Halaman Login dan Register React yang berbicara ke API **lewat gateway**.
- Menyimpan token di **memory** (React context), bukan `localStorage`.
- Satu klien API yang mengubah semua error menjadi satu bentuk (`ApiError`).
- Route terproteksi dan _component test_ dengan Testing Library.

## Kondisi awal

Backend lengkap di balik gateway (34 tes lulus). Frontend masih halaman placeholder
dari m0.2.

```bash
git switch starter/m4.1-frontend-auth
npm ci && npm run build:packages
```

## Konsep singkat

```
LoginPage ─ useAuth().login() ─▶ AuthContext ─ api.login() ─▶ fetch(VITE_API_BASE_URL + '/auth/login')
                                    │ simpan token di state React
DashboardPage ◀─ ProtectedRoute ◀───┘ (tanpa token → <Navigate to="/login">)
```

Mengapa token tidak disimpan di `localStorage`? Skrip apa pun yang berhasil disisipkan
ke halaman (XSS) bisa membaca `localStorage`. Token di memory lebih sulit dicuri.
Konsekuensinya: setelah halaman di-refresh, pengguna harus login lagi. Di materi
lanjutan (m12.3), masalah ini diselesaikan dengan refresh token di cookie HttpOnly.

## Langkah-langkah

### Langkah 1 — Klien API (`frontend/src/api/client.ts`)

```ts
const BASE_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080';

export class ApiError extends Error {
  constructor(
    message: string,
    public status: number,
    public code?: string,
    public details?: unknown,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}
```

Fungsi `request<T>(path, { method, body, token })`:

1. Header `content-type: application/json`; bila ada token, `authorization: Bearer <token>`.
2. `fetch` gagal (server mati, jaringan putus) → `ApiError('Tidak dapat menghubungi server', 0, 'NETWORK')`.
3. Baca body sebagai **teks** dulu, lalu coba `JSON.parse` di dalam `try`. Proxy yang
   gagal bisa menjawab HTML, dan `JSON.parse` pada HTML akan melempar error yang tidak
   ramah.
4. `!res.ok` → ambil `data.error.message` dan `data.error.code` (bentuk seragam dari
   m1.2), lalu lempar `ApiError`.
5. Berhasil → kembalikan `data as T`.

Lalu ekspor objek `api` berisi `register`, `login`, `me`, `products`, `createOrder`, dan `health`. Khusus `health`, jangan melempar error untuk 503: widget di m4.2 justru butuh body-nya. Bila gateway tak terjangkau, kembalikan `{ status: 'degraded', gateway: 'down', services: {} }`.

> `VITE_API_BASE_URL` dibaca saat **build**, bukan saat aplikasi berjalan. Nilainya
> ditanam ke dalam berkas JavaScript hasil build. Ini akan penting di m4.3.

### Langkah 2 — `AuthContext` (`frontend/src/context/AuthContext.tsx`)

```tsx
export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [token, setToken] = useState<string | null>(null);
  const value = useMemo<AuthState>(
    () => ({
      user,
      token,
      async login(email, password) {
        const res = await api.login(email, password);
        setToken(res.token);
        setUser(res.user);
      },
      async register(email, password) {
        await api.register(email, password);
        const res = await api.login(email, password); // langsung masuk setelah daftar
        setToken(res.token);
        setUser(res.user);
      },
      logout() {
        setToken(null);
        setUser(null);
      },
    }),
    [user, token],
  );
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth harus dipakai di dalam AuthProvider');
  return ctx;
}
```

### Langkah 3 — Route terproteksi dan routing

`ProtectedRoute`:

```tsx
export function ProtectedRoute({ children }: { children: ReactNode }) {
  const { token } = useAuth();
  return token ? <>{children}</> : <Navigate to="/login" replace />;
}
```

`App.tsx` membungkus semuanya dengan `<AuthProvider>` dan `<BrowserRouter>`, dengan
route `/login`, `/register`, `/dashboard` (terproteksi), dan pengalihan `/` serta `*`
ke `/dashboard`.

| Berkas                    | Isi                                                                                                                               |

| `pages/LoginPage.tsx`     | form email + password, judul **"Masuk"**, panggil `login`, lalu `navigate('/dashboard')`; tampilkan `err.message` bila `ApiError` |

Pakai kelas Tailwind dengan token brand (`bg-primary`, `text-muted`, dan sebagainya).
Setiap `<input>` diberi `<label>` dan atribut `autoComplete` (`username`,
`current-password`, `new-password`) supaya bisa diakses pembaca layar dan password
manager.

### Langkah 5 — Persiapan tes

Buat `frontend/src/test/setup.ts`:


dari `vitest run --passWithNoTests` menjadi `vitest run`.

## Bila ada masalah

| Gejala                                          | Solusi                                                                             |
| ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| Error CORS di console browser                   | Origin frontend (`http://localhost:5173`) harus sama dengan `CORS_ORIGIN` gateway. |
| Setelah refresh harus login lagi                | Memang disengaja di lab ini (token hanya di memory).                               |
| Tes: `Invalid Chai property: toBeInTheDocument` | `setup.ts` belum ada atau `test.setupFiles` salah alamat.                          |
| Tes gagal karena `fetch` sungguhan dipanggil    | `vi.stubGlobal('fetch', ...)` harus dipasang di `beforeEach`, sebelum `render`.    |
