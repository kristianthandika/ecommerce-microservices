# m4.3 — Containerization per Service

| Branch awal                     | Kunci jawaban                    | Waktu     | Sebelumnya | Berikutnya |
| ------------------------------- | -------------------------------- | --------- | ---------- | ---------- |
| `starter/m4.3-containerization` | `solution/m4.3-containerization` | 120 menit | m4.2       | m4.4       |

## Yang akan Anda pelajari

- Dockerfile **multi-stage**: alat build di stage pertama, runtime ramping di stage kedua.
- Menjalankan container sebagai user **non-root**.
- Mengapa build context harus **root repo** pada monorepo.
- Menyajikan frontend dengan **nginx**, termasuk _SPA fallback_.

## Kondisi awal

Sistem lengkap berjalan dengan `npm run dev:all`. product-service dan order-service
sudah punya `Dockerfile` (dibuat bersama service-nya di m2.1/m2.3); auth-service,
gateway, dan frontend belum. Pelajari salah satu yang sudah ada sebagai contoh.

```bash
git switch starter/m4.3-containerization
npm ci && npm run build:packages
docker version            # Docker Desktop harus berjalan
cat services/product-service/Dockerfile
```

## Konsep singkat

**Multi-stage.** Stage `build` berisi compiler C++ (untuk `bcrypt`), semua dependency
pengembangan, dan TypeScript. Stage `runtime` hanya menyalin hasil yang dibutuhkan.
Image akhir jauh lebih kecil dan berisi lebih sedikit perangkat yang bisa
disalahgunakan penyerang.

**Build context = root repo.** `@ecommerce/logger` tinggal di `packages/`, di luar
folder service. Bila context-nya `services/auth-service`, Docker tidak bisa melihat
`packages/` sama sekali. Karena itu semua image dibangun dari root:

```bash
docker build -f services/auth-service/Dockerfile .      # titik di akhir = root repo
```

**Alpine di kedua stage.** `bcrypt` memakai kode native. Binary yang dikompilasi di
Linux biasa (glibc) tidak bisa dimuat di Alpine (musl). Gunakan `node:24-alpine` di
build dan runtime.

## Langkah-langkah

### Langkah 1 — `.dockerignore` di root

```
**/node_modules
**/dist
**/coverage
.git
.gitignore
**/*.log
.env
.env.local
services/auth-service/keys
**/loadtest-*.txt
**/loadtest-*.json
```

Tanpa berkas ini, `node_modules` lokal (ratusan MB, dan berisi binary untuk sistem
operasi Anda) ikut dikirim ke Docker dan bisa merusak image. Kunci RSA lokal juga
tidak boleh ikut masuk image.

### Langkah 2 — `services/auth-service/Dockerfile`

```dockerfile
# ---- build ----
FROM node:24-alpine AS build
WORKDIR /app
RUN apk add --no-cache python3 make g++          # toolchain untuk bcrypt
# Semua manifest workspace dulu: layer npm ci tetap di-cache selama dependency tidak berubah.
COPY package.json package-lock.json ./
COPY packages/logger/package.json packages/logger/
COPY packages/resilient-http-client/package.json packages/resilient-http-client/
COPY services/auth-service/package.json services/auth-service/
COPY services/product-service/package.json services/product-service/
COPY services/order-service/package.json services/order-service/
COPY services/gateway/package.json services/gateway/
COPY frontend/package.json frontend/
RUN npm ci
COPY tsconfig.base.json ./
COPY packages ./packages
RUN npm run build:packages
RUN npm prune --omit=dev                          # buang dependency pengembangan

# ---- runtime ----
FROM node:24-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/package.json ./package.json
COPY --from=build /app/packages ./packages
COPY services/auth-service ./services/auth-service
# Folder kunci harus milik user node SEBELUM berpindah user.
RUN mkdir -p /app/services/auth-service/keys && chown -R node:node /app/services/auth-service/keys
USER node
WORKDIR /app/services/auth-service
EXPOSE 3001
CMD ["node", "src/index.ts"]
```

### Langkah 3 — `services/gateway/Dockerfile`

Pola yang sama dengan auth-service, tetapi tanpa folder `keys`, dengan
`COPY services/gateway ./services/gateway`, `WORKDIR /app/services/gateway`, dan
`EXPOSE 8080`.

### Langkah 4 — Frontend dengan nginx

`frontend/Dockerfile`:

```dockerfile
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
# (salin semua package.json workspace seperti di atas)
RUN npm ci --workspace=frontend --include-workspace-root   # hanya dependency frontend
ARG VITE_API_BASE_URL=http://localhost:8080
ENV VITE_API_BASE_URL=$VITE_API_BASE_URL                   # ditanam saat build!
COPY frontend ./frontend
RUN npm run build --workspace=frontend

FROM nginx:1.27-alpine AS runtime
COPY --from=build /app/frontend/dist /usr/share/nginx/html
COPY frontend/nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

`frontend/nginx.conf`:

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    location /assets/ { expires 1y; }               # berkas ber-hash boleh di-cache lama
    location / { try_files $uri $uri/ /index.html; } # SPA fallback
}
```

Tanpa `try_files ... /index.html`, membuka `http://localhost:3000/dashboard` langsung
(atau menekan refresh di sana) menghasilkan 404, karena tidak ada berkas bernama
`dashboard` di server.

### Langkah 5 — Build dan periksa

```bash
docker build -t lab-auth -f services/auth-service/Dockerfile .
docker build -t lab-gateway -f services/gateway/Dockerfile .
docker build -t lab-frontend -f frontend/Dockerfile .
docker images | grep lab-                         # bandingkan ukurannya
docker run --rm lab-auth whoami                   # harus "node", bukan "root"
docker run --rm -p 3001:3001 lab-auth             # lalu: curl localhost:3001/health
docker run --rm -p 3000:80 lab-frontend           # buka localhost:3000/dashboard, lalu refresh
```

Frontend di dalam container belum bisa login, karena gateway belum berjalan di
jaringan yang sama. Itu diselesaikan Docker Compose di m4.4.

## Kriteria lulus

- [ ] Ketiga image ter-build dari root repo tanpa error.
- [ ] `whoami` di container service mencetak `node`.
- [ ] Refresh di `/dashboard` pada container frontend tidak menghasilkan 404.
- [ ] Image multi-stage lebih kecil daripada image satu stage yang menyalin seluruh
      `node_modules` (coba buat versi naifnya untuk membandingkan).
- [ ] `npm test` tetap lulus (35 tes).

## Bila ada masalah

| Gejala                                                  | Solusi                                                                                |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `COPY failed: ... packages/logger` / "module not found" | Build context bukan root repo. Jalankan `docker build` dari root dengan `.` di akhir. |
| `Error loading shared library ... bcrypt`               | Stage build dan runtime memakai image dasar berbeda. Pakai Alpine di keduanya.        |
| `EACCES: permission denied, mkdir ... keys`             | `chown` folder `keys` ke `node` harus dijalankan **sebelum** `USER node`.             |
| `npm ci` di Docker gagal: lockfile tidak sinkron        | Ada `package.json` workspace yang tidak di-`COPY` sebelum `npm ci`.                   |
