## Yang akan Anda pelajari

- Alur atur ulang password lewat tautan email yang **sekali pakai**.
- Mengapa mengganti password harus **mengakhiri semua sesi**.
- Menjaga pemeriksaan dan perubahan tetap atomik, supaya satu tautan tidak bisa dipakai dua kali.

## Konsep singkat

```
POST /auth/password-reset { email }        → 202 yang sama untuk alamat mana pun
       (bila alamat punya akun: email berisi /reset-password#token=..., berlaku 1 jam)
POST /auth/password-reset/confirm { token, password }
       → password baru, akun terverifikasi, SEMUA sesi berakhir → pengguna login lagi
```

Orang biasanya mengatur ulang password karena **curiga password lamanya diketahui orang
lain**. Bila sesi lama tetap hidup, penyerang yang sudah masuk tetap di dalam. Karena
itu, dalam satu transaksi yang sama dengan penggantian password:

- semua token reset milik akun itu dihapus (tautan sekali pakai);
- semua tautan verifikasi email akun itu dihapus (`forgetVerifications`);
- semua sesi berakhir (`endAllSessions`): refresh token ditolak, dan access token yang
  masih beredar masuk daftar pencabutan (m12.7);
- semua device cookie dilupakan (`forgetDevices`, m12.11).

Tautan reset membuktikan penguasaan kotak surat, jadi akun sekaligus ditandai
terverifikasi. Inilah jalan bagi pemilik alamat untuk mengambil alih akun yang
didaftarkan orang lain atas nama emailnya.

## Langkah-langkah

### Langkah 1 — Impor

```ts
import { endAllSessions } from './sessions.ts';
import { forgetDevices } from './devices.ts';
import { forgetVerifications } from './verification.ts';
```

### Langkah 2 — Tulis ulang `confirmPasswordReset`

```ts
const key = hash(token);
const record = resets.get(key);
if (!record || record.expiresAt <= now) throw invalid();
const passwordHash = await hashPassword(password); // bcrypt di luar transaksi

const user = database.transaction(() => {
  const current = resets.get(key); // baca ulang: dua request, satu pemenang
  if (!current || current.expiresAt <= now) return null;
  const updated = replacePassword(current.userId, passwordHash);
  if (!updated) return null;
  database
    .statement(
      "DELETE FROM records WHERE namespace='password_resets' AND json_extract(value, '$.userId')=?",
    )
    .run(current.userId);
  forgetVerifications(current.userId);
  endAllSessions(current.userId, 'password-reset', now);
  forgetDevices(current.userId);
  return updated;
});
if (!user) throw invalid();
return user;
```

`endAllSessions` (di `sessions.ts`) mencabut setiap keluarga sesi akun itu, tetapi hanya
memasukkan ke daftar pencabutan sesi yang access token-nya masih mungkin berlaku.
Daftar itu tetap pendek walau satu akun punya banyak sesi lama.

### Langkah 3 — Coba di browser

1. Login, lalu buka tab kedua dan login juga di sana.
2. Keluar dari tab pertama, klik **Lupa password?** di halaman masuk, isi email Anda.
3. Buka kotak surat pelatihan sebagai admin, klik tautan atur ulang, pilih password baru.
4. Kembali ke tab kedua dan muat ulang: sesinya sudah berakhir.

## Bila ada masalah

| Gejala                                         | Solusi                                                     |
| ---------------------------------------------- | ---------------------------------------------------------- |
| Tautan bisa dipakai dua kali                   | Token reset tidak dihapus, atau dihapus di luar transaksi. |
| Tautan verifikasi pendaftar lain masih berlaku | `forgetVerifications` belum dipanggil.                     |
| `await` di dalam transaksi ditolak             | Hitung `hashPassword` sebelum `database.transaction`.      |
