# m12.3 — Refresh Token Berotasi dan Logout yang Mencabut Sesi

| Branch awal                     | Kunci jawaban                    | Waktu    | Sebelumnya | Berikutnya |
| ------------------------------- | -------------------------------- | -------- | ---------- | ---------- |
| `starter/m12.3-refresh-session` | `solution/m12.3-refresh-session` | 90 menit | m12.2      | m12.4      |

## Yang akan Anda pelajari

- Access token pendek (15 menit) tanpa memaksa pengguna login ulang setiap 15 menit.
- **Rotasi** refresh token: setiap token hanya bisa dipakai sekali.
- Mendeteksi token yang dicuri, dan membedakannya dari dua tab yang me-refresh bersamaan.

## Kondisi awal

`rotateSession` dan `endSession` di `services/auth-service/src/sessions.ts` menjawab
`501`. Login dan cookie sudah berjalan, jadi pengguna bisa masuk tetapi sesinya tidak
bisa diperpanjang dan logout gagal.

```bash
git switch starter/m12.3-refresh-session
npm ci && npm run build:packages
npm test --workspace=services/auth-service
```

Tes yang gagal di starter (kebanyakan di `tests/sessions.test.ts`):

- `rotates on every refresh and returns the current user and role`
- `treats a concurrent refresh in another tab as a race, not as theft`
- `revokes the whole session when an old refresh token is replayed later`
- `logout revokes the session and clears the cookie`
- `stops accepting the access token of a session that logged out`
- `revokes access tokens too when a stolen refresh token is detected`
- `revokes a signed access token even when its refresh cookie is missing`
- `still revokes a valid cookie when the bearer is invalid or expired`
- `rejects cross-site refresh attempts (CSRF) and requests without a cookie`
- `publishes no entry for a session whose access token has already expired`
- `ends every session of an account at once, listing only the ones still usable`
- `ends a session whose account is no longer verified at the next refresh` (`verification.test.ts`)
- `sets the new password once, ends every session and forgets known devices` (`password-reset.test.ts`)

## Konsep singkat

```
login ─▶ keluarga sesi F (sid), refresh token R1 (cookie HttpOnly), access token A1 (memory)
refresh(R1) ─▶ R1 ditandai rotatedAt, terbit R2 + A2
refresh(R2) ─▶ R2 ditandai, terbit R3 + A3
refresh(R1) lagi, 1 menit kemudian ─▶ "R1 sudah pernah dipakai!" ─▶ cabut SELURUH keluarga F
```

Bila R1 dipakai lagi setelah dirotasi, ada dua orang yang memegangnya: pemilik dan
pencuri. Server tidak tahu yang mana, jadi semua token keluarga itu dicabut dan
keduanya harus login lagi. Pengecualiannya: dalam 10 detik
(`config.refresh.reuseGraceMs`), pemakaian ulang hampir pasti tab kedua milik
pengguna yang sama, jadi dijawab `409 REFRESH_RACE` tanpa mencabut apa pun.

Token tidak pernah disimpan mentah. Database menyimpan `hash(token)` (SHA-256), dan
pencarian dilakukan dengan hash itu.

## Langkah-langkah

### Langkah 1 — Pahami fungsi yang sudah ada

Baca di `sessions.ts`: `hash()`, `mint()` (menerbitkan token baru dan mencatat sampai
kapan access token terbarunya berlaku), `startSession()`, `revokeFamily()`, dan tipe
`RotationResult`.

### Langkah 2 — `rotateSession(token, now)`

Semua dalam `database.transaction(() => { ... })`. Tanpa transaksi, dua request
bersamaan dengan token yang sama bisa sama-sama berhasil.

```ts
const invalid = () =>
  new AppError(401, 'Sesi berakhir. Silakan masuk kembali.', undefined, 'INVALID_REFRESH');
```

1. `record = tokens.get(hash(token))`; tidak ada → `throw invalid()`.
2. `family = families.get(record.familyId)`; tidak ada, `family.revokedAt` terisi, atau
   `now >= family.expiresAt` → `throw invalid()`.
3. `record.rotatedAt !== undefined`:
   - `now - record.rotatedAt <= config.refresh.reuseGraceMs` →
     `AppError(409, 'Sesi sedang diperbarui di tab lain. Coba lagi.', undefined, 'REFRESH_RACE')`;
   - selain itu → `revokeFamily(record.familyId, 'reuse', now)` lalu
     `return { kind: 'reused', userId: record.userId }`.
4. `now >= record.expiresAt` → `throw invalid()`.
5. `tokens.set(key, { ...record, rotatedAt: now })` lalu
   `return { kind: 'rotated', userId, familyId, ...mint(userId, familyId, now) }`.

Letakkan fungsi `invalid` di level modul (starter menghapusnya karena belum dipakai).

### Langkah 3 — `endSession(token, now)`

```ts
database.transaction(() => {
  const record = tokens.get(hash(token));
  if (record) revokeFamily(record.familyId, 'logout', now);
});
```

Token yang tidak dikenal diabaikan: logout harus bisa diulang tanpa error.

### Langkah 4 — Telusuri route-nya

Buka `services/auth-service/src/routes.ts`, route `/refresh` dan `/logout`. Perhatikan:
cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`, header `Cache-Control:
no-store`, dan `requireSameSiteRequest` (perlindungan CSRF tiga lapis).

## Kriteria lulus

- [ ] Semua tes di atas lulus; tidak ada tes lain yang gagal.
- [ ] Dua request refresh paralel dengan token sama: satu `200`, satu `409`.

## Bila ada masalah

| Gejala                                 | Solusi                                                                      |
| -------------------------------------- | --------------------------------------------------------------------------- |
| Dua request paralel sama-sama berhasil | Pemeriksaan dan penandaan `rotatedAt` harus dalam satu transaksi.           |
| Dua tab membuat pengguna ter-logout    | Pemakaian ulang dalam jendela grace harus 409, bukan pencabutan.            |
| Logout tidak berefek di service lain   | Yang dicabut adalah keluarga sesi (`revokeFamily`), bukan hanya satu token. |
| `'invalid' is declared but never read` | Anda menulis `invalid` tetapi belum memakainya; selesaikan langkah 2.       |
