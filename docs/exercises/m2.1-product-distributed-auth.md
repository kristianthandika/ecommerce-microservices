# m2.1 — product-service & Distributed Auth

| Branch awal                             | Kunci jawaban                            | Waktu     | Sebelumnya | Berikutnya |
| --------------------------------------- | ---------------------------------------- | --------- | ---------- | ---------- |
| `starter/m2.1-product-distributed-auth` | `solution/m2.1-product-distributed-auth` | 120 menit | m1.3       | m2.2       |

## Yang akan Anda pelajari

- Membuat service kedua dengan pola yang sama seperti auth-service.
- Memverifikasi JWT **tanpa** memanggil auth-service di setiap request (`jwks-rsa` + cache).
- Membatasi akses berdasarkan peran (RBAC): baca katalog publik, ubah katalog hanya admin.

## Kondisi awal

auth-service lengkap dari m1.3 (register, login, JWKS, `/me`) dengan 7 tes lulus.

```bash
git switch starter/m2.1-product-distributed-auth
npm ci && npm run build:packages
npm test       # 7 tes auth-service lulus
```

## Konsep singkat

Bila setiap request ke product-service harus bertanya "token ini sah?" ke
auth-service, auth-service menjadi titik lemah: lambat atau mati, semua ikut mati.
Dengan JWT RS256 hal itu tidak perlu. product-service cukup mengambil **kunci publik**
satu kali dari `GET /.well-known/jwks.json`, menyimpannya di memory, lalu memeriksa
tanda tangan setiap token sendiri.

## Langkah-langkah

### Langkah 1 — Salin pola service dari auth-service

```bash
mkdir -p services/product-service/src/middleware services/product-service/tests
cp services/auth-service/tsconfig.json services/product-service/
cp services/auth-service/src/middleware/{errors,validate}.ts services/product-service/src/middleware/
cp services/auth-service/src/types.d.ts services/product-service/src/
```

Buat `services/product-service/package.json` seperti milik auth-service, dengan
`"name": "product-service"`, dan dependency `jwks-rsa` serta `jsonwebtoken` sebagai
ganti `bcrypt`. Lalu `npm install`.

`src/config.ts`:

```ts
export const config = {
  serviceName: 'product-service',
  port: Number(process.env.PORT || process.env.PRODUCT_SERVICE_PORT || 3002),
  authServiceUrl: process.env.AUTH_SERVICE_URL || 'http://localhost:3001',
  jwtIssuer: process.env.JWT_ISSUER || 'auth-service',
  corsOrigin: process.env.CORS_ORIGIN || 'http://localhost:5173',
} as const;
```

Salin juga `src/app.ts` dan `src/index.ts` dari auth-service, lalu sesuaikan nama
service. `index.ts` di sini tidak butuh kunci RSA maupun admin seed.

### Langkah 2 — Penyimpanan produk (`src/products.ts`)

`Map<string, Product>` di memory, diisi tiga produk contoh saat modul dimuat:

```ts
export interface Product {
  id: string;
  name: string;
  price: number;
  stock: number;
}
export type ProductInput = Omit<Product, 'id'>;
```

Fungsi: `listProducts()`, `getProduct(id)` (tidak ada → `AppError(404, 'Produk tidak
ditemukan', undefined, 'NOT_FOUND')`), `createProduct(data)`, `updateProduct(id, data)`,
`deleteProduct(id)`.

### Langkah 3 — Verifikasi JWT lewat JWKS (`src/middleware/require-auth.ts`)

```ts
const client = new JwksClient({
  jwksUri: `${config.authServiceUrl}/.well-known/jwks.json`,
  cache: true,
  cacheMaxEntries: 5,
  cacheMaxAge: 10 * 60 * 1000, // 10 menit
  timeout: 3000,
});
```

Urutan kerja `requireAuth`:

1. Ambil token dari header `Authorization: Bearer <token>`; tidak ada → 401.
2. Baca header token **tanpa** memverifikasinya: `jwt.decode(token, { complete: true })?.header`.
   Tidak ada `kid` → 401.
3. `client.getSigningKey(kid)` lalu `.getPublicKey()`. Gagal → 401 "Tidak bisa
   memverifikasi token".
4. `jwt.verify(token, publicKey, { algorithms: ['RS256'], issuer: config.jwtIssuer })`.
   Gagal → 401. Berhasil → simpan klaimnya di `req.user`, lalu `next()`.

Fungsi ini `async`; Express 5 meneruskan error yang dilemparnya ke error handler.

### Langkah 4 — RBAC (`src/middleware/require-role.ts`)

```ts
export function requireRole(...allowed: string[]) {
  return (req: Request, _res: Response, next: NextFunction): void => {
    if (!req.user) throw new AppError(401, 'Belum terautentikasi');
    if (!allowed.includes(String(req.user.role)))
      throw new AppError(403, 'Akses ditolak: role tidak mencukupi', undefined, 'FORBIDDEN');
    next();
  };
}
```

Bedakan **401** (siapa Anda? belum login / token salah) dari **403** (saya tahu siapa
Anda, tetapi Anda tidak boleh).

### Langkah 5 — Route (`src/routes.ts`)

```ts
const productSchema = z.object({
  name: z.string().min(1, 'Nama produk wajib diisi').max(200),
  price: z.number().positive('Harga harus lebih dari 0').max(1_000_000_000),
  stock: z.number().int().nonnegative('Stok tidak boleh negatif').max(1_000_000).default(0),
});
```

| Method & path          | Middleware                                                             |
| ---------------------- | ---------------------------------------------------------------------- |
| `GET /health`          | -                                                                      |
| `GET /products`        | publik                                                                 |
| `GET /products/:id`    | publik                                                                 |
| `POST /products`       | `requireAuth, requireRole('admin'), validate(productSchema)` → 201     |
| `PUT /products/:id`    | `requireAuth, requireRole('admin'), validate(productSchema.partial())` |
| `DELETE /products/:id` | `requireAuth, requireRole('admin')` → 204                              |

### Langkah 6 — Coba bersama auth-service

```bash
npm run dev --workspace=services/auth-service       # terminal 1
npm run dev --workspace=services/product-service    # terminal 2
# terminal 3: login sebagai admin demo, lalu buat produk
TOKEN=$(curl -s -X POST localhost:3001/login -H 'content-type: application/json' \
  -d '{"email":"admin@inixindo.local","password":"admin123"}' | node -pe 'JSON.parse(require("fs").readFileSync(0)).token')
curl -s -X POST localhost:3002/products -H "authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' -d '{"name":"Topi","price":50000,"stock":5}'
```

Lalu hentikan auth-service (Ctrl+C di terminal 1) dan ulangi `POST /products`.
Masih berhasil, karena kunci publik sudah tersimpan di cache product-service.

## Menguji hasil kerja

```bash
git checkout solution/m2.1-product-distributed-auth -- services/product-service/tests
npm test --workspace=services/product-service
```

Tes memakai server JWKS **palsu** yang menghitung berapa kali ia dipanggil, sehingga
tidak butuh auth-service sungguhan. Tes yang harus lulus:

- `GET /products publik → 200`
- `POST tanpa token → 401`
- `POST dengan token non-admin → 403 (RBAC)`
- `POST admin dengan body invalid → 400 (bukan 500)`
- `POST admin valid → 201 (panggilan PERTAMA memicu fetch JWKS)`
- `setelah auth-service MATI, verifikasi token berikutnya TETAP berhasil (cache jwks-rsa)`

## Kriteria lulus

- [ ] Keenam tes product-service dan tujuh tes auth-service lulus.
- [ ] URL auth-service dibaca dari `AUTH_SERVICE_URL`, tidak ditulis langsung di kode.
- [ ] Non-admin mendapat 403, tanpa token 401, body salah 400.

## Bila ada masalah

| Gejala                                     | Solusi                                                                                                                                       |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `ECONNREFUSED` ke auth-service             | Jalankan auth-service, atau periksa `AUTH_SERVICE_URL`. Jangan menulis `http://auth-service:3001` di kode: nama itu hanya berlaku di Docker. |
| JWKS terambil tetapi verifikasi gagal      | `kid` di header token tidak sama dengan `kid` di JWKS. Periksa `keyid` saat `jwt.sign`.                                                      |
| Tes: env `AUTH_SERVICE_URL` tidak terpakai | `JwksClient` dibuat saat modul diimpor. Tes harus mengisi env **sebelum** `import('../src/app.ts')`.                                         |
