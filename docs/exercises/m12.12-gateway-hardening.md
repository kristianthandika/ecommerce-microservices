## Yang akan Anda pelajari

- **Path normalization bypass**: path yang terlihat aman bagi penjaga, tetapi menjadi
  path berbahaya setelah dinormalisasi oleh komponen berikutnya.
- Gateway sebagai **pemegang tunggal** kebijakan CORS dan cache.
- Batas waktu request, supaya klien lambat tidak bisa menahan koneksi selamanya.

## Konsep singkat

**Bypass penjaga route internal.** auth-service punya route internal
`GET /internal/revocations` untuk service lain (m12.7). Gateway meneruskan semua path di
bawah `/auth`, jadi ia memblokir path yang cocok dengan pola `/<service>/internal`.
Masalahnya, proxy membentuk URL tujuan dengan parser URL WHATWG, yang:

| Path yang diterima gateway          | Path yang dikirim proxy |
| ----------------------------------- | ----------------------- |
| `/v1/auth/./internal/revocations`   | `/internal/revocations` |
| `/v1/auth/%2e/internal/revocations` | `/internal/revocations` |
| `/v1/auth/.\internal/revocations`   | `/internal/revocations` |

Penjaga yang hanya melihat kolom kiri tidak melihat kata `internal` di posisi yang
diblokir, jadi request itu lolos. Lapis kedua (service token) masih menahannya, tetapi
satu lapis pertahanan sudah jebol. Aturannya: **periksa apa yang akan dikirim, bukan
hanya apa yang diterima.**

**Header di tepi.** Setiap service punya bawaan CORS sendiri untuk pengembangan
(`http://localhost:5173`). Bila header itu diteruskan apa adanya, ia menimpa kebijakan
`CORS_ORIGIN` gateway. Respons berisi data pengguna (pesanan, keranjang) juga tidak
boleh disimpan browser atau proxy perantara.

## Langkah-langkah

### Langkah 1 — Normalisasi seperti proxy

Di atas `isInternalPath`, tambahkan dua fungsi bantu:

```ts
function decodePath(path: string): string {
  try {
    return decodeURIComponent(path);
  } catch {
    return path;
  } // escape rusak: apa adanya
}

/** Path seperti hasil parser URL (segmen titik hilang, `\` menjadi `/`). */
function normalizePath(path: string): string | undefined {
  try {
    // Satu garis miring di depan: `//host/...` tidak boleh terbaca sebagai nama host.
    return new URL(path.replace(/^[/\\]+/, '/'), 'http://gateway.invalid').pathname;
  } catch {
    return undefined;
  }
}
```

Lalu ubah `isInternalPath`: tolak bila **salah satu** tafsiran cocok dengan
`INTERNAL_PATH`, yaitu path yang sudah di-decode, path yang dinormalisasi, dan path yang
di-decode lalu dinormalisasi (contoh `.%2Finternal`):

```ts
const path = url.split('?')[0];
const decoded = decodePath(path);
return [decoded, normalizePath(path), normalizePath(decoded)].some(
  (candidate) => candidate !== undefined && INTERNAL_PATH.test(decodePath(candidate)),
);
```

### Langkah 2 — Kebijakan header di tepi

```ts
export function edgeResponseHeaders(headers: IncomingHttpHeaders): IncomingHttpHeaders {
  const result: IncomingHttpHeaders = {};
  for (const [name, value] of Object.entries(headers))
    if (!name.toLowerCase().startsWith('access-control-')) result[name] = value;
  result['cache-control'] ??= 'no-store'; // service yang boleh di-cache (JWKS) menyatakannya sendiri
  return result;
}
```

Fungsi ini sudah dipasang sebagai `rewriteHeaders` di `proxyOptions`.

### Langkah 3 — Batas waktu request

Di opsi `Fastify({ ... })`, tambahkan:

```ts
requestTimeout: config.requestTimeoutMs,   // GATEWAY_REQUEST_TIMEOUT_MS, bawaan 15 detik
```

Perhatikan juga opsi `undici` di `proxyOptions` yang sudah ada: `headersTimeout` dan
`bodyTimeout` (upstream yang menggantung dijawab 504), serta
`connect: { rejectUnauthorized: true }` (bawaan `@fastify/reply-from` **tidak**
memverifikasi sertifikat upstream HTTPS).

### Langkah 4 — Buktikan dengan request mentah

`curl` menormalisasi path sebelum mengirim, jadi pakai `--path-as-is`:

```bash
curl -s --path-as-is localhost:8080/v1/auth/./internal/revocations
# starter: diteruskan ke auth-service (dijawab 401 karena tidak ada service token)
# solution: 404 NOT_FOUND dari gateway, tidak pernah sampai ke auth-service
```

(Lewat nginx di port 3000 hasilnya sudah 404, karena nginx menormalisasi URL lebih
dulu. Port 8080 hanya terbuka untuk `127.0.0.1`.)

## Bila ada masalah

| Gejala                                   | Solusi                                                              |
| ---------------------------------------- | ------------------------------------------------------------------- |
| `/v1/products?q=internal` ikut terblokir | Hanya bagian sebelum `?` yang diperiksa.                            |
| `//internal` terbaca sebagai nama host   | Ganti garis miring berganda di depan dengan satu sebelum `new URL`. |
| JWKS ikut `no-store`                     | Pakai `??=`, bukan `=`; JWKS mengirim `Cache-Control` sendiri.      |
