# m1.3 — Register/Login, JWT RS256, dan JWKS

| Branch awal                  | Kunci jawaban                 | Waktu     | Sebelumnya | Berikutnya |
| ---------------------------- | ----------------------------- | --------- | ---------- | ---------- |

## Yang akan Anda pelajari

- Menyimpan password dengan aman (bcrypt) dan login tanpa membocorkan email mana yang terdaftar.
- Menandatangani JWT dengan kunci **privat** RSA (RS256), sehingga service lain cukup
  memegang kunci **publik** untuk memverifikasinya.
- Menerbitkan kunci publik lewat endpoint standar **JWKS** dengan `kid` yang stabil.

## Kondisi awal

auth-service dari m1.2: `/health`, `/boom`, error handler, validasi. Tes
`tests/bootstrap.test.ts` lulus.

```bash
git switch starter/m1.3-auth-jwt-jwks
npm ci && npm run build:packages
npm test --workspace=services/auth-service     # 4 tes bootstrap lulus
```

## Konsep singkat

```
klien ── POST /login ──▶ auth-service  (punya private.pem)
       ◀── JWT ─────────  ditandatangani dengan kunci privat, header berisi "kid"

klien ── GET /products (Authorization: Bearer <JWT>) ──▶ product-service
                                  product-service mengambil kunci publik sekali dari
                                  auth-service /.well-known/jwks.json, lalu memverifikasi
                                  sendiri setiap token tanpa bertanya lagi.
```

`kid` (key ID) adalah nama kunci. Header JWT dan entri di JWKS harus memuat `kid`
yang sama, supaya verifier tahu kunci mana yang dipakai.

## Langkah-langkah

### Langkah 1 — Tambahkan dependency

```bash
npm install bcrypt jsonwebtoken --workspace=services/auth-service
npm install -D @types/bcrypt @types/jsonwebtoken --workspace=services/auth-service
```

(Di solution keduanya sudah tercantum; perintah ini aman diulang.)

### Langkah 2 — Kunci RSA: muat atau buat sekali (`src/keys.ts`)

Tambahkan ke `config.ts`:

```ts
keysDir: process.env.KEYS_DIR || resolve(dirname(fileURLToPath(import.meta.url)), '..', 'keys'),
jwt: { issuer: process.env.JWT_ISSUER || 'auth-service', expiresIn: process.env.JWT_EXPIRES_IN || '1h' },
bcryptSaltRounds: Number(process.env.BCRYPT_SALT_ROUNDS || 10),
seedAdmin: {
  email: process.env.SEED_ADMIN_EMAIL || 'admin@inixindo.local',
  password: process.env.SEED_ADMIN_PASSWORD || 'admin123',
},
```

`src/keys.ts` mengekspor `getKeyMaterial()` yang:

1. bila `keys/private.pem` **dan** `keys/public.pem` sudah ada → **membacanya**;
2. bila belum → `generateKeyPairSync('rsa', { modulusLength: 2048, ... })`, membuat
   folder, lalu menyimpan keduanya (`private.pem` dengan `mode: 0o600`);
3. menghitung `kid` sebagai _JWK thumbprint_ (RFC 7638): SHA-256 dari
   `JSON.stringify({ e, kty, n })` kunci publik, dalam base64url;
4. membuat JWK publik `{ ...createPublicKey(pem).export({ format: 'jwk' }), kid, use: 'sig', alg: 'RS256' }`;
5. menyimpan hasilnya di variabel modul (cache) supaya hanya dihitung sekali.

Tambahkan juga `export function _resetKeyCache()` (mengosongkan cache) untuk tes.

> Mengapa wajib "muat dulu"? Bila kunci dibuat ulang setiap start, restart service
> membuat semua token yang sudah beredar langsung tidak berlaku.

### Langkah 3 — Penyimpanan pengguna (`src/users.ts`)

Untuk tahap ini pengguna disimpan **di memory** (`Map`), terindeks berdasarkan email dan
id. Database sungguhan datang di materi lanjutan.

```ts
interface User {
  id: string;
  email: string;
  role: 'user' | 'admin';
  passwordHash: string;
}
const usersByEmail = new Map<string, User>();
const usersById = new Map<string, User>();
```

Fungsi yang dibutuhkan:

| Fungsi                          | Perilaku                                                                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `register({ email, password })` | email sudah ada → `AppError(409, …, 'EMAIL_TAKEN')`; selain itu `bcrypt.hash`, simpan dengan role **`user`**                                                                                                 |
| `login({ email, password })`    | **selalu** jalankan `bcrypt.compare`, juga untuk email tak dikenal (bandingkan dengan hash umpan); salah → `AppError(401, 'Email atau password salah', …, 'INVALID_CREDENTIALS')`; benar → `{ token, user }` |
| `getUserById(id)`               | pengguna tanpa `passwordHash`, atau `null`                                                                                                                                                                   |
| `seedAdmin(logger)`             | membuat satu admin demo dari `config.seedAdmin` bila belum ada                                                                                                                                               |
| `_resetUsers()`                 | mengosongkan kedua `Map` (untuk tes)                                                                                                                                                                         |

Fungsi penanda tangan token:

```ts
function signToken(user: User): string {
  const { privateKeyPem, kid } = getKeyMaterial();
  return jwt.sign({ email: user.email, role: user.role }, privateKeyPem, {
    algorithm: 'RS256',
    keyid: kid, // menjadi header.kid
    subject: user.id, // klaim "sub"
    issuer: config.jwt.issuer,
    expiresIn: config.jwt.expiresIn as unknown as number,
  });
}
```

> **Hash umpan.** Bila email tidak dikenal lalu fungsi langsung menjawab, jawabannya
> jauh lebih cepat daripada untuk email terdaftar (bcrypt sengaja lambat). Penyerang
> bisa mengukur selisih waktu itu untuk mengetahui email mana yang terdaftar. Karena
> itu hitung sekali `bcrypt.hashSync('dummy…')` dan bandingkan password dengannya.

### Langkah 4 — Verifikasi token di auth-service (`src/middleware/require-auth.ts`)

```ts
export function requireAuth(req: Request, _res: Response, next: NextFunction): void {
  const [scheme, token] = (req.headers.authorization || '').split(' ');
  if (scheme !== 'Bearer' || !token) throw new AppError(401, 'Token tidak ada atau format salah');
  try {
    req.user = jwt.verify(token, getKeyMaterial().publicKeyPem, {
      algorithms: ['RS256'], // tolak algoritma lain, termasuk "none"
      issuer: config.jwt.issuer,
    }) as JwtPayload;
  } catch {
    throw new AppError(401, 'Token tidak valid');
  }
  next();
}
```

Tambahkan `user?: JwtPayload` ke deklarasi `Request` di `src/types.d.ts`.

### Langkah 5 — Route

Di `src/routes.ts`: hapus `/boom`, lalu tambahkan

```ts
const credentialsSchema = z.object({
  email: z.string().email('Email tidak valid').max(254),
  password: z.string().min(8, 'Password minimal 8 karakter').max(200), // batas atas: cegah DoS bcrypt
});

router.get('/.well-known/jwks.json', (_req, res) => res.json({ keys: [getKeyMaterial().jwk] }));
router.post('/register', validate(credentialsSchema), async (req, res) => {
  res.status(201).json({ user: await register(req.validated as Credentials) });
});
router.post('/login', validate(credentialsSchema), async (req, res) => {
  res.json(await login(req.validated as Credentials));
});
router.get('/me', requireAuth, (req, res) =>
  res.json({ user: getUserById(String(req.user?.sub)) }),
);
```

### Langkah 6 — Siapkan kunci dan admin saat start

Di `src/index.ts`, sebelum `listen`:

```ts
const { kid } = getKeyMaterial();
logger.info({ kid }, 'keypair RS256 siap');
await seedAdmin(logger);
```

`await` di level atas berkas diperbolehkan karena proyek memakai ES module.

### Langkah 7 — Coba alurnya

```bash
npm run dev --workspace=services/auth-service
# terminal lain:
curl -s -X POST localhost:3001/register -H 'content-type: application/json' \
  -d '{"email":"budi@contoh.id","password":"rahasia123"}'
TOKEN=$(curl -s -X POST localhost:3001/login -H 'content-type: application/json' \
  -d '{"email":"budi@contoh.id","password":"rahasia123"}' | node -pe 'JSON.parse(require("fs").readFileSync(0)).token')
curl -s localhost:3001/me -H "authorization: Bearer $TOKEN"
curl -s localhost:3001/.well-known/jwks.json
```

Tempel token ke https://jwt.io (hanya token latihan!) untuk melihat header `kid` dan
klaim `sub`, `role`, `iss`, `exp`.

## Bila ada masalah

| Gejala                                | Solusi                                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `bcrypt.compare` selalu `false`       | Urutan argumennya `compare(passwordPolos, hash)`.                                                             |
| Service lain: `signing key not found` | `export({ format: 'jwk' })` tidak menghasilkan `kid`. Tambahkan `kid` ke JWK **dan** `keyid` saat `jwt.sign`. |
| Token tidak berlaku setelah restart   | `getKeyMaterial` membuat kunci baru setiap start; periksa cabang "muat dari berkas".                          |
| `bcrypt` gagal dipasang di Windows    | Gunakan Node 24 terbaru; bcrypt 6 menyediakan binary siap pakai. Ulangi `npm ci`.                             |
