
## Konsep singkat

**Monorepo** berarti semua bagian sistem (library, service, frontend) tinggal di satu
repo. **npm workspaces** membuat npm memperlakukan setiap folder sebagai paket
tersendiri, tetapi memasang dependency bersama di satu `node_modules` di root. Satu
`npm ci` cukup untuk semuanya, dan paket internal bisa saling memakai dengan nama
seperti `@ecommerce/logger`.

Struktur yang akan dipakai sepanjang pelatihan:

```
packages/   library bersama (logger, http client, storage)
services/   auth-service, product-service, order-service, gateway
frontend/   aplikasi React
```

## Langkah-langkah

### Langkah 1 — Buat `package.json` root

Buat berkas `package.json` di root repo:

```json
{
  "name": "ecommerce-microservices",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "engines": { "node": ">=24" },
  "workspaces": ["packages/*", "services/*", "frontend"],
  "scripts": {
    "build:packages": "npm run build --workspace=packages/logger --workspace=packages/resilient-http-client",
    "test": "npm run test --workspaces --if-present",
    "typecheck": "npm run typecheck --workspaces --if-present",
    "lint": "eslint .",
    "format": "prettier --write ."
  }
}
```

Penjelasan bagian penting:

- `"private": true` mencegah paket ini terbit ke npm secara tidak sengaja.
- `"type": "module"` membuat semua berkas `.js`/`.ts` memakai `import`/`export`.
- `"workspaces"` memberi tahu npm di folder mana saja paket-paket berada. Folder itu
  boleh belum ada sekarang.
- Skrip `test` dan `typecheck` menjalankan skrip dengan nama yang sama di **setiap**
  workspace; `--if-present` melewati workspace yang tidak punya skrip itu.

### Langkah 2 — Pasang alat pengembangan

```bash
npm install --save-dev typescript @types/node eslint @eslint/js typescript-eslint globals prettier vitest concurrently
```

Perintah ini membuat `node_modules/` dan `package-lock.json`. **Commit
`package-lock.json`**: berkas itulah yang membuat `npm ci` peserta lain memasang
versi yang persis sama.

### Langkah 3 — Konfigurasi TypeScript bersama

Buat `tsconfig.base.json`. Setiap workspace nanti punya `tsconfig.json` kecil yang
`extends` berkas ini.

```json
{
  "compilerOptions": {
    "target": "ES2023",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "lib": ["ES2023"],
    "types": ["node"],
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "allowImportingTsExtensions": true,
    "rewriteRelativeImportExtensions": true,
    "declaration": true,
    "sourceMap": true
  }
}
```

`allowImportingTsExtensions` memungkinkan `import { x } from './x.ts'`. Node 24
menjalankan berkas `.ts` langsung, dan Node mewajibkan ekstensi berkas ditulis
lengkap pada `import`.

### Langkah 4 — ESLint dan Prettier

`eslint.config.js`:

```js
import js from '@eslint/js';
import globals from 'globals';
import tseslint from 'typescript-eslint';

export default tseslint.config(
  { ignores: ['**/node_modules/**', '**/dist/**', '**/coverage/**', 'frontend/**'] },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    languageOptions: { ecmaVersion: 2024, sourceType: 'module', globals: { ...globals.node } },
    rules: {
      '@typescript-eslint/no-unused-vars': [
        'warn',
        { argsIgnorePattern: '^_', varsIgnorePattern: '^_' },
      ],
    },
  },
);
```

`.prettierrc.json`:

```json
{ "singleQuote": true, "semi": true, "printWidth": 100, "trailingComma": "all", "tabWidth": 2 }
```

### Langkah 5 — Contoh environment variable

Buat `.env.example` berisi port dan URL antar-service. Berkas ini dicommit sebagai
contoh; berkas `.env` yang asli **tidak** pernah dicommit (sudah ada di
`.gitignore`).

```
LOG_LEVEL=info
AUTH_SERVICE_PORT=3001
PRODUCT_SERVICE_PORT=3002
ORDER_SERVICE_PORT=3003
GATEWAY_PORT=8080
AUTH_SERVICE_URL=http://localhost:3001
PRODUCT_SERVICE_URL=http://localhost:3002
ORDER_SERVICE_URL=http://localhost:3003
```

Prinsipnya: service tidak boleh menulis alamat service lain di dalam kode. Alamat
selalu dibaca dari environment, dengan default `localhost` untuk pengembangan.

## Menguji hasil kerja

```bash
npm install            # sukses, tanpa error
npx eslint .           # tanpa error (belum ada kode untuk diperiksa)
npx prettier --check . # semua berkas rapi; bila tidak, jalankan: npm run format
```

`npm test`, `npm run typecheck`, dan `npm run build:packages` **masih gagal** dengan
pesan `No workspaces found`. Itu wajar: workspace pertama baru dibuat di m0.2.

## Kriteria lulus

- [ ] `package.json` root berisi `workspaces` untuk `packages/*`, `services/*`, `frontend`.
- [ ] `package-lock.json` ada dan ikut dicommit.
- [ ] `tsconfig.base.json`, `eslint.config.js`, `.prettierrc.json`, `.env.example` ada.
- [ ] `npm install` dan `npx eslint .` berjalan tanpa error.

## Bila ada masalah

| Gejala                                     | Solusi                                                                            |
| ------------------------------------------ | --------------------------------------------------------------------------------- |
| `npm ERR! Unsupported engine`              | Node.js Anda bukan versi 24. Periksa `node -v`.                                   |
| ESLint: `Cannot use import statement`      | Pastikan `"type": "module"` ada di `package.json` root.                           |
| Nanti: "Cannot find module" paket internal | Jalankan `npm ls --workspaces` dan cocokkan pola `workspaces` dengan nama folder. |
