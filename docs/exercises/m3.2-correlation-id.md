# m3.2 — Correlation ID dan Korelasi Log

| Branch awal                   | Kunci jawaban                  | Waktu    | Sebelumnya | Berikutnya |
| ----------------------------- | ------------------------------ | -------- | ---------- | ---------- |
| `starter/m3.2-correlation-id` | `solution/m3.2-correlation-id` | 60 menit | m3.1       | m3.3       |

## Yang akan Anda pelajari

- Memberi setiap request satu ID yang ikut berpindah dari gateway → order-service →
  product-service.
- Memakai ID itu untuk menelusuri satu request di log beberapa service.

## Kondisi awal

Gateway dari m3.1 dengan 6 tes lulus. Logger (`createHttpLogger`, m0.2) dan
order-service (`fetchProduct`, m2.3) **sudah** siap membaca dan meneruskan header
`x-correlation-id`. Yang belum ada: gateway yang membuat dan meneruskannya.

```bash
git switch starter/m3.2-correlation-id
npm ci && npm run build:packages
npm test --workspace=services/gateway     # 6 tes lulus
```

## Konsep singkat

Tanpa correlation ID, satu error di product-service hanya terlihat sebagai baris log
terpisah; Anda tidak tahu request pengguna mana yang memicunya. Dengan ID yang sama
di setiap hop, cukup cari satu nilai:

```bash
docker compose logs | grep 3f6c2a1e-...      # nanti di m4.4
```

Aturannya:

1. Gateway memakai `x-correlation-id` dari klien bila ada, atau membuat UUID baru.
2. Gateway memantulkan ID itu ke response, supaya klien bisa menyebutkannya saat lapor bug.
3. Gateway meneruskan ID yang **sama** ke service di belakangnya.
4. Service yang memanggil service lain juga meneruskannya, tidak membuat ID baru.

## Langkah-langkah

### Langkah 1 — `genReqId` di Fastify

Di `src/app.ts`, beri tahu Fastify cara membuat `request.id`:

```ts
import { randomUUID } from 'node:crypto';
import type { IncomingMessage } from 'node:http';
import { createLogger, CORRELATION_ID_HEADER } from '@ecommerce/logger';

const app = Fastify({
  loggerInstance: createLogger('gateway') as unknown as FastifyBaseLogger,
  genReqId(req: IncomingMessage) {
    const h = req.headers[CORRELATION_ID_HEADER];
    return (Array.isArray(h) ? h[0] : h) || randomUUID();
  },
  trustProxy: false,
});
```

Fastify otomatis menyertakan `request.id` di setiap baris log request itu.

### Langkah 2 — Satu hook untuk ID dan IP klien (`src/correlation.ts`)

Pindahkan hook `X-Forwarded-For` dari m3.1 ke berkas baru dan tambahkan correlation ID:

```ts
export function attachCorrelation(
  request: FastifyRequest,
  reply: FastifyReply,
  done: HookHandlerDoneFunction,
): void {
  const id = request.id;
  reply.header(CORRELATION_ID_HEADER, id); // pantulkan ke klien
  request.raw.headers[CORRELATION_ID_HEADER] = id; // teruskan ke service
  request.raw.headers['x-forwarded-for'] = request.ip;
  request.raw.headers['x-real-ip'] = request.ip;
  done();
}
```

`@fastify/http-proxy` meneruskan `request.raw.headers` apa adanya, jadi mengubah
objek itu cukup untuk meneruskan header ke service.

Di `app.ts`, ganti hook lama dengan `app.addHook('onRequest', attachCorrelation)`.

### Langkah 3 — Periksa hop kedua

Buka `services/order-service/src/product-client.ts` dan `routes.ts`. Pastikan
`POST /orders` meneruskan `req.id` (correlation ID dari logger) ke `fetchProduct`,
dan `fetchProduct` mengirimnya sebagai header `x-correlation-id`. Bagian ini sudah
dibuat di m2.3; di sini Anda membuktikan bahwa rantainya utuh.

### Langkah 4 — Buktikan di log

```bash
LOG_LEVEL=info npm run dev:all
# terminal lain: login, lalu buat pesanan lewat gateway dengan ID buatan sendiri
curl -s -X POST localhost:8080/orders -H "authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' -H 'x-correlation-id: coba-korelasi-1' \
  -d '{"items":[{"productId":"<id produk>","quantity":1}]}'
```

Di terminal `dev:all`, cari `coba-korelasi-1`. Nilai itu muncul di log **gateway,
order-service, dan product-service**.

## Kriteria lulus

- [ ] Delapan tes gateway dan semua tes sebelumnya lulus.
- [ ] Satu request gateway → order → product menghasilkan correlation ID yang sama
      di log ketiga service.

## Bila ada masalah

| Gejala                                  | Solusi                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------ |
| ID hilang di product-service            | order-service membuat ID baru alih-alih meneruskan `req.id`. Periksa `fetchProduct`. |
| Response tidak punya `x-correlation-id` | `reply.header(...)` belum dipanggil di hook.                                         |
| ID berbeda di gateway dan service       | Hook memakai `randomUUID()` lagi; pakai `request.id` yang dibuat `genReqId`.         |
