# m12.11 — Device Cookie Anti-Lockout

## Yang akan Anda pelajari

- Efek samping backoff login per akun: penyerang bisa **mengunci** korban.
- Pola **device cookie** dari OWASP: browser yang pernah berhasil masuk punya
  penghitung kegagalannya sendiri.
- Menyimpan token hanya sebagai hash, dan membatasi nilai token yang dicuri.

## Kondisi awal

Login sudah memasang cookie `device_id`, tetapi `services/auth-service/src/devices.ts`
tidak pernah mengingatnya: `issueDevice` hanya membuat token acak, `isTrustedDevice`
selalu `false`, dan `recordDeviceFailure` kosong. Cari tanda `TODO m12.11`.

Tes yang gagal:

- `password-reset.test.ts`: `sets the new password once, ends every session and forgets known devices`

## Konsep singkat

Setelah lima password salah, email itu ditahan 30 detik, lalu 60 detik, dan seterusnya
sampai 15 menit (`assertLoginAllowed` di `sessions.ts`). Bagus untuk menghentikan
penebak password, tetapi penyerang yang **tidak** ingin masuk cukup mengirim lima
password salah setiap beberapa menit, dan pemilik akun tidak pernah bisa login.

Device cookie memisahkan keduanya:

| Request login                                 | Penghitung yang dipakai                      |
| --------------------------------------------- | -------------------------------------------- |
| tanpa cookie, atau cookie milik akun lain     | penghitung bersama per email (bisa terkunci) |
| dengan cookie yang diterbitkan untuk akun ini | penghitung milik cookie itu sendiri          |

Penyerang tidak punya cookie korban, jadi kunci yang ia buat hanya berlaku untuk klien
yang belum pernah dipakai korban. Cookie ini **bukan** kredensial: tanpa password yang
benar, ia tidak membuat siapa pun masuk. Setelah lima password salah, cookie itu
dihapus, sehingga cookie curian hanya memberi beberapa tebakan.

Di database hanya disimpan `hash(token)` (SHA-256). Siapa pun yang membaca database
tidak mendapat cookie yang bisa dipakai.

## Langkah-langkah

### Langkah 1 — `issueDevice(userId, presented, now)`

```ts
const token = randomBytes(32).toString('base64url');
const expiresAt = now + config.device.ttlMs; // 90 hari
database.transaction(() => {
  if (presented && devices.get(hash(presented))?.userId === userId) devices.delete(hash(presented)); // rotasi: cookie lama pensiun
  devices.insert(hash(token), { userId, failures: 0, expiresAt }, expiresAt);
});
return { token, expiresAt };
```

Hapus baris `void hash;` di akhir berkas; `hash` kini benar-benar dipakai.

### Langkah 2 — `isTrustedDevice(token, userId, now)`

```ts
if (!token) return false;
const device = devices.get(hash(token));
return device !== undefined && device.userId === userId && device.expiresAt > now;
```

Pemeriksaan `device.userId === userId` mencegah cookie milik akun A membuka kunci akun B.

### Langkah 3 — `recordDeviceFailure(token)`

```ts
database.transaction(() => {
  const key = hash(token);
  const device = devices.get(key);
  if (!device) return;
  if (device.failures + 1 >= config.device.maxFailures) devices.delete(key);
  else devices.set(key, { ...device, failures: device.failures + 1 });
});
```

### Langkah 4 — Telusuri pemakaiannya

Di `users.ts`, `login(credentials, deviceToken)` memakai `isTrustedDevice` untuk memilih
penghitung. Di `routes.ts`, `sendDeviceCookie` memasang cookie dengan atribut yang sama
seperti refresh token (`HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`) setiap
kali login, verifikasi email, atau reset password berhasil.

- [ ] Ketiga tes di atas lulus; tidak ada tes lain yang gagal.

## Bila ada masalah

| Gejala                                       | Solusi                                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Cookie akun lain membuka kunci               | `isTrustedDevice` tidak membandingkan `userId`.                                           |
| Cookie curian bisa menebak tanpa batas       | `recordDeviceFailure` tidak menghapus cookie pada batasnya.                               |
| Perangkat lama tetap dipercaya setelah reset | `forgetDevices` (sudah ada) menghapus berdasarkan `userId`; pastikan field itu tersimpan. |
