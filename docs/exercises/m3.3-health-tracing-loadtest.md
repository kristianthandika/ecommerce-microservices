## Yang akan Anda pelajari

- Satu endpoint `/health` yang melaporkan status **semua** service.
- Tracing pengantar dengan OpenTelemetry: setiap request di gateway menghasilkan _span_.
- Mengukur kapasitas gateway dengan load test `autocannon`.

## Kondisi awal

Gateway dari m3.2 (proxy, rate limit, correlation ID), 8 tes gateway lulus.

```bash
git switch starter/m3.3-health-tracing-loadtest
npm ci && npm run build:packages
```

## Konsep singkat

**Health agregat.** Frontend (m4.2) dan Docker (m4.4) perlu tahu apakah sistem sehat.
Gateway bertanya ke `/health` setiap service **secara paralel**, masing-masing dengan
batas waktu. Satu service yang lambat tidak boleh membuat `/health` ikut lambat.

| Kondisi              | HTTP  | Body                                                       |
| -------------------- | ----- | ---------------------------------------------------------- |
| semua service sehat  | `200` | `{ status: 'ok', gateway: 'up', services: {...} }`         |
| ada yang mati/lambat | `503` | `{ status: 'degraded', ..., services: { order: 'down' } }` |

**Tracing.** Span adalah catatan "operasi X mulai jam sekian, selesai jam sekian".
Di lab ini span cukup dicetak ke console. Sistem produksi mengirimnya ke Jaeger,
Tempo, atau sejenisnya.

## Langkah-langkah

### Langkah 1 — Health agregat (`src/health.ts`)

Tambahkan `healthTimeoutMs: Number(process.env.HEALTH_TIMEOUT_MS || 1000)` ke
`config.ts`, lalu:

```ts
const fetchWithTimeout = withTimeout(fetch, config.healthTimeoutMs); // dari m2.2

async function probe(url: string, correlationId: string): Promise<'up' | 'down'> {
  try {
    const res = await fetchWithTimeout(`${url}/health`, {
      headers: { [CORRELATION_ID_HEADER]: correlationId },
    });
    return res.ok ? 'up' : 'down';
  } catch {
    return 'down'; // timeout atau koneksi ditolak = down, bukan error 500
  }
}

export async function aggregatedHealth(
  request: FastifyRequest,
  reply: FastifyReply,
): Promise<void> {
  const entries = Object.entries(config.services);
  const results = await Promise.all(entries.map(([, url]) => probe(url, String(request.id))));
  const services = Object.fromEntries(entries.map(([name], i) => [name, results[i]]));
  const allUp = results.every((s) => s === 'up');
  reply.code(allUp ? 200 : 503).send({
    status: allUp ? 'ok' : 'degraded',
    gateway: 'up',
    services,
    timestamp: new Date().toISOString(),
  });
}
```

Daftarkan di `app.ts`: `app.get('/health', aggregatedHealth);`. Gateway memakai
`@ecommerce/resilient-http-client`, jadi tambahkan `"@ecommerce/resilient-http-client": "*"`
ke dependency gateway.

### Langkah 2 — Tracing (`src/tracing.ts`)

```bash
npm install @opentelemetry/api @opentelemetry/sdk-node @opentelemetry/sdk-trace-node @fastify/otel --workspace=services/gateway
```

```ts
const fastifyOtel = new FastifyOtelInstrumentation({
  servername: 'gateway',
  registerOnInitialization: false,
});
let sdk: NodeSDK | undefined;

export function startTracing(): NodeSDK {
  if (sdk) return sdk;
  sdk = new NodeSDK({
    serviceName: 'gateway',
    traceExporter: new ConsoleSpanExporter(),
    instrumentations: [fastifyOtel],
  });
  sdk.start();
  return sdk;
}
export const getFastifyOtelPlugin = () => fastifyOtel.plugin() as unknown as FastifyPluginCallback;
export async function shutdownTracing(): Promise<void> {
  if (sdk) await sdk.shutdown();
}
```

> **Penting.** Gunakan `@fastify/otel`. Paket lama `@opentelemetry/instrumentation-fastify`
> sudah usang, dan `auto-instrumentations-node` versi terbaru tidak lagi mencakup
> Fastify. Kalau salah paket, tidak ada error sama sekali; span-nya saja yang tidak
> pernah muncul. Karena itu selalu buktikan dengan request sungguhan.

### Langkah 3 — Pasang tracing di gateway

- `buildApp({ enableTracing = true } = {})`: bila `enableTracing`, daftarkan
  `getFastifyOtelPlugin()` **sebelum** plugin lain. Tes memanggil
  `buildApp({ enableTracing: false })` supaya console tes tidak penuh span.
- `index.ts`: panggil `startTracing()` **sebelum** `buildApp`, dan `shutdownTracing()`
  saat shutdown.

### Langkah 4 — Load test (`scripts/loadtest.ts`)

```bash
npm install -D autocannon @types/autocannon --workspace=services/gateway
```

Skrip memanggil `autocannon({ url, connections, duration }, callback)`. Di callback,
cetak `autocannon.printResult(result)` dan simpan ke `loadtest-<timestamp>.txt`. URL,
jumlah koneksi, dan durasi dibaca dari `GATEWAY_URL`, `LOADTEST_CONNECTIONS`,
`LOADTEST_DURATION`. Tambahkan skrip `"loadtest": "node scripts/loadtest.ts"` di
`package.json` gateway.

### Langkah 5 — Coba

```bash
npm run dev:all
curl -s localhost:8080/health          # semua "up", HTTP 200
# hentikan order-service saja, lalu:
curl -i localhost:8080/health          # HTTP 503, "order":"down"
npm run loadtest                       # dari root; hasil di services/gateway/loadtest-*.txt
```

Saat `dev:all` berjalan, setiap request ke gateway mencetak blok span (berisi
`traceId`, `name`, `duration`) di console gateway.

## Menguji hasil kerja

```bash
git checkout solution/m3.3-health-tracing-loadtest -- services/gateway/tests
npm test --workspace=services/gateway
```

Solution berisi tes gateway lengkap yang menggantikan tes m3.1/m3.2. Tes yang harus lulus:

- `proxy /products diteruskan ke product-service`
- `meneruskan correlation ID YANG SAMA ke service & memantulkannya ke response`
- `generate correlation ID kalau klien tidak mengirimnya`
- `meneruskan IP klien asli lewat X-Forwarded-For / X-Real-IP (anti-spoof)`
- `security header (helmet) muncul di response gateway`
- `header rate-limit aktif di level gateway`
- `aggregated /health → ok saat semua up, degraded saat ada yang down`

## Bila ada masalah

| Gejala                                  | Solusi                                                                              |
| --------------------------------------- | ----------------------------------------------------------------------------------- |
| Span tidak pernah muncul                | Paket instrumentasi salah, atau `startTracing()` dipanggil setelah `buildApp()`.    |
| `/health` lambat saat satu service mati | Probe tidak memakai `withTimeout`, atau dijalankan berurutan (bukan `Promise.all`). |
| `/health` menjawab 500                  | Error koneksi tidak ditangkap di `probe`; harus menjadi `'down'`.                   |
