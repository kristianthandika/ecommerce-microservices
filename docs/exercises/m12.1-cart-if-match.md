# m12.1 — Konkurensi keranjang dengan If-Match/ETag (Starter)

**Tujuan:** mencegah _lost update_ memakai mekanisme standar HTTP (RFC 9110 §13.1.1, RFC 6585), bukan field `version` di body.
**Yang perlu dibangun:** `services/order-service/src/middleware/precondition.ts` — `cartPrecondition` membaca `If-Match: "<version>"` (412 bila usang, 428 bila tidak ada, 400 bila formatnya salah) dan tetap menerima `version` di body sebagai jalur lama bertanda `Deprecation`; `sendCartVersion` mengirim `ETag` dan `Cache-Control: no-store`. Di starter hanya jalur body lama yang bekerja.
**Acceptance:** `npm test --workspace=services/order-service` lulus, termasuk _exposes the cart version as a strong, uncached ETag_ dan _requires a precondition and rejects stale or malformed ones_. Suite E2E belanja (jalur lama) tetap lulus.

## Cara Debugging

- Selalu 400 → ETag dikirim dengan tanda kutip (`"abc"`); buang kutipnya sebelum membandingkan dengan versi.
- 409 padahal header dikirim → konflik jalur header adalah 412; 409 hanya untuk jalur body lama.
- `DELETE` kehilangan versi → jangan membaca body pada DELETE; proxy boleh membuangnya.
- Browser memakai versi lama → respons keranjang wajib `Cache-Control: no-store`.
