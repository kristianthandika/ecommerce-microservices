# m12.1 — Konkurensi Keranjang dengan If-Match/ETag

## Yang akan Anda pelajari

- Masalah **lost update**: dua tab mengubah keranjang yang sama, satu perubahan hilang diam-diam.
- Mencegahnya dengan mekanisme standar HTTP: `ETag` dan `If-Match` (RFC 9110), plus
  `412 Precondition Failed` dan `428 Precondition Required` (RFC 6585).
- Mempertahankan klien lama selama masa transisi, dengan header `Deprecation`.


Tiga tes ini **gagal** di starter, dan harus lulus di akhir lab:

- `exposes the cart version as a strong, uncached ETag`
- `requires a precondition and rejects stale or malformed ones`
- `still accepts the deprecated body version for one release, flagged as deprecated`

## Konsep singkat

```
GET /cart              → 200, ETag: "v1"
PUT /cart/items/A      If-Match: "v1"   → 200, ETag: "v2"     (tab 1 menang)
PUT /cart/items/B      If-Match: "v1"   → 412 Precondition Failed   (tab 2: muat ulang dulu)
PUT /cart/items/B      (tanpa If-Match) → 428 Precondition Required
```

Setiap perubahan keranjang menghasilkan `version` (UUID) baru. Server hanya menerima
perubahan dari klien yang membuktikan bahwa ia melihat versi terbaru.

## Langkah-langkah

### Langkah 1 — Kirim versi sebagai ETag

Isi `sendCartVersion(res, version)`:

```ts
res.set('ETag', `"${version}"`); // ETag selalu diapit tanda kutip
res.set('Cache-Control', 'no-store'); // harga dan stok adalah data langsung
```

Jalankan tes; tes pertama sekarang lulus.

### Langkah 2 — Baca `If-Match`

Di `cartPrecondition(req, res)`, sebelum jalur lama:

1. `const header = req.get('if-match')`.
2. Bila ada: cocokkan dengan `/^"([^"]+)"$/` setelah `trim()`, lalu validasi isinya
   dengan `versionSchema.safeParse(...)` (UUID). Tidak cocok →
   `AppError(400, 'If-Match harus berisi satu ETag keranjang, mis. "<version>"', undefined, 'INVALID_PRECONDITION')`.
3. Cocok → `return { version, conflictStatus: 412 }`.

`conflictStatus` dipakai `changeItem` di `cart.ts` saat versinya ternyata usang.

### Langkah 3 — Jalur lama dan jalur kosong

- `version` di body valid → `res.set('Deprecation', BODY_VERSION_DEPRECATED)` lalu
  `return { version, conflictStatus: 409 }`. Klien lama tetap mendapat 409 seperti dulu.
- Tidak ada keduanya → `AppError(428, 'Header If-Match wajib diisi dengan ETag keranjang terbaru', undefined, 'PRECONDITION_REQUIRED')`.

Parameter `res` di starter bernama `_res` karena belum dipakai. Ganti menjadi `res`.

### Langkah 4 — Lihat dari sisi frontend

Buka `frontend/src/api/client.ts` dan cari `ifMatch`. Frontend mengirim
`If-Match: "<version>"` dari keranjang yang terakhir ia baca. Coba di browser dengan
dua tab yang menampilkan keranjang yang sama.

## Bila ada masalah

| Gejala                     | Solusi                                                                     |
| -------------------------- | -------------------------------------------------------------------------- |
| Selalu 400                 | Buang tanda kutip ETag sebelum membandingkan dengan versi.                 |
| 409 padahal header dikirim | Konflik lewat header harus 412; 409 hanya untuk jalur body lama.           |
| `DELETE` kehilangan versi  | Jangan membaca body pada DELETE; sebagian proxy membuangnya. Pakai header. |
| Browser memakai versi lama | Respons keranjang wajib `Cache-Control: no-store`.                         |
