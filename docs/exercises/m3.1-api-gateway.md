# m3.1 — API Gateway dengan Fastify

| Branch awal                | Kunci jawaban               | Waktu     | Sebelumnya | Berikutnya |
| -------------------------- | --------------------------- | --------- | ---------- | ---------- |
| `starter/m3.1-api-gateway` | `solution/m3.1-api-gateway` | 120 menit | m2.3       | m3.2       |

## Yang akan Anda pelajari

- Gateway sebagai **satu-satunya pintu masuk** API (pola Backend-for-Frontend).
- Reverse proxy dengan `@fastify/http-proxy`, termasuk memotong prefix path.
- Memusatkan rate limit, security header, dan CORS di satu tempat.
- Meneruskan IP klien asli dengan aman (anti-spoofing `X-Forwarded-For`).

## Kondisi awal

Tiga service Express (auth, product, order) dengan 27 tes lulus. Klien harus tahu
tiga alamat berbeda.

```bash
git switch starter/m3.1-api-gateway
npm ci && npm run build:packages
```

## Konsep singkat

```
klien ──▶ gateway :8080 ──/auth/*─────▶ auth-service :3001     (prefix /auth dibuang)
                       ──/products/*──▶ product-service :3002
                       ──/orders/*────▶ order-service :3003
```

Mengapa Fastify untuk gateway padahal service lain Express? Gateway meneruskan
**semua** lalu lintas, jadi performa dan plugin proxy yang matang lebih penting di
sini. Pelatihan ini sengaja memakai keduanya.

Soal `X-Forwarded-For`: header ini memberi tahu service di belakang alamat IP klien
yang asli. Klien jahat bisa mengirim `X-Forwarded-For: 1.2.3.4` sendiri untuk
mengelabui rate limit. Karena gateway adalah batas kepercayaan, gateway **menimpa**
header itu dengan IP yang benar-benar ia lihat, tidak meneruskan kiriman klien.

## Langkah-langkah

### Langkah 1 — Workspace gateway

```bash
mkdir -p services/gateway/src services/gateway/tests
cp services/auth-service/tsconfig.json services/gateway/
```

`services/gateway/package.json`: nama `gateway`, skrip `dev`/`start`/`test`/`typecheck`
seperti service lain, dan dependency:

```bash
npm install fastify @fastify/http-proxy @fastify/rate-limit @fastify/helmet @fastify/cors --workspace=services/gateway
```

Tambahkan juga `"@ecommerce/logger": "*"` ke `dependencies`.

### Langkah 2 — Konfigurasi (`src/config.ts`)

```ts
export const config = {
  serviceName: 'gateway',
  port: Number(process.env.PORT || process.env.GATEWAY_PORT || 8080),
  host: process.env.HOST || '0.0.0.0',
  services: {
    auth: process.env.AUTH_SERVICE_URL || 'http://localhost:3001',
    product: process.env.PRODUCT_SERVICE_URL || 'http://localhost:3002',
    order: process.env.ORDER_SERVICE_URL || 'http://localhost:3003',
  },
  corsOrigin: process.env.CORS_ORIGIN || 'http://localhost:5173',
  rateLimit: {
    max: Number(process.env.GATEWAY_RATE_LIMIT_MAX || 100),
    timeWindow: process.env.GATEWAY_RATE_LIMIT_WINDOW || '1 minute',
  },
} as const;
```

### Langkah 3 — `buildApp()` (`src/app.ts`)

Sama seperti `createApp()` di Express: fungsi ini **tidak** memanggil `listen`, supaya
tes bisa memakainya dengan `app.inject()`.

```ts
export async function buildApp(): Promise<FastifyInstance> {
  const app = Fastify({
    loggerInstance: createLogger('gateway') as unknown as FastifyBaseLogger,
    trustProxy: false, // gateway = batas kepercayaan: abaikan XFF dari klien
  });

  await app.register(helmet, { global: true });
  await app.register(cors, { origin: config.corsOrigin, credentials: true });
  await app.register(rateLimit, {
    max: config.rateLimit.max,
    timeWindow: config.rateLimit.timeWindow,
  });

  app.addHook('onRequest', (request, _reply, done) => {
    request.raw.headers['x-forwarded-for'] = request.ip; // TIMPA, jangan teruskan
    request.raw.headers['x-real-ip'] = request.ip;
    done();
  });

  app.get('/', async () => ({ service: 'gateway', status: 'ok' }));

  await app.register(httpProxy, {
    upstream: config.services.auth,
    prefix: '/auth',
    rewritePrefix: '',
  });
  await app.register(httpProxy, {
    upstream: config.services.product,
    prefix: '/products',
    rewritePrefix: '/products',
  });
  await app.register(httpProxy, {
    upstream: config.services.order,
    prefix: '/orders',
    rewritePrefix: '/orders',
  });
  return app;
}
```

`rewritePrefix: ''` artinya `/auth/login` di gateway tiba di auth-service sebagai
`/login`. Prefix `/products` dan `/orders` dipertahankan karena route di service
memang memakai path itu.

### Langkah 4 — Titik masuk (`src/index.ts`)

```ts
const app = await buildApp();
try {
  await app.listen({ port: config.port, host: config.host });
} catch (err) {
  app.log.error(err, 'gagal start gateway');
  process.exit(1);
}
for (const signal of ['SIGTERM', 'SIGINT'] as const)
  process.on(signal, async () => {
    await app.close();
    process.exit(0);
  });
```

### Langkah 5 — Coba seluruh sistem

```bash
npm run dev:all        # auth, product, order, gateway sekaligus
# terminal lain:
curl -i localhost:8080/products                 # diteruskan ke product-service
curl -s -X POST localhost:8080/auth/login -H 'content-type: application/json' \
  -d '{"email":"admin@inixindo.local","password":"admin123"}'
```

Perhatikan header `x-ratelimit-limit: 100` dan `x-content-type-options: nosniff` di
setiap jawaban gateway.

## Menguji hasil kerja

```bash
git checkout solution/m3.1-api-gateway -- services/gateway/tests
npm test --workspace=services/gateway
```

Tes memakai `app.inject()` (request diproses tanpa membuka port) dan tiga server
"cermin" yang memantulkan path serta header yang mereka terima. Tes yang harus lulus:

- `meneruskan /products ke product-service dengan path yang sama`
- `meneruskan /orders ke order-service`
- `memotong prefix /auth: /auth/login tiba di auth-service sebagai /login`
- `menimpa X-Forwarded-For kiriman klien dengan IP yang diamati gateway (anti-spoof)`
- `security header (helmet) muncul di response gateway`
- `header rate-limit aktif di level gateway`

## Kriteria lulus

- [ ] Keenam tes gateway dan semua tes sebelumnya lulus.
- [ ] Ketiga service bisa dijangkau lewat gateway di port 8080.
- [ ] `X-Forwarded-For` yang dikirim klien tidak pernah sampai ke service.

## Bila ada masalah

| Gejala                          | Solusi                                                                                                                                 |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 502/503 dari gateway            | Periksa service tujuannya langsung (`curl localhost:3002/health`) untuk memisahkan masalah gateway dari service mati.                  |
| `/auth/login` jadi 404          | `rewritePrefix` untuk auth harus `''`.                                                                                                 |
| 429 terlalu cepat               | Ada dua lapis rate limit (gateway 100/menit, service 300/15 menit). Itu disengaja; jangan buat limit service lebih ketat dari gateway. |
| `FST_ERR_PLUGIN_...` saat start | Setiap `app.register(...)` harus di-`await`.                                                                                           |
